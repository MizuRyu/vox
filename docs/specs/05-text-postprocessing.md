# 05 テキスト後処理 — 辞書と訂正

状態: 未実装（将来）。現在の本体で動いているのはフィラー除去だけで、辞書と訂正 UI は設計のみ。

最終確認日: 2026-09-07

現在実装しているのは規則ベースのフィラー除去（[ADR-012](../adr/012-filler-removal-rule-based.md)）です。以下の辞書・訂正は将来の設計で、本体には入っていません。

## 辞書

**初版の訂正: 「CoreML 変換済みモデルには hotword biasing の公開 API が存在しない」は誤りでした。**
FluidAudio に本物の文脈バイアス API が公開されています。

- `configureVocabularyBoosting(vocabulary:ctcModels:config:)`
- `CustomVocabularyContext` / `CustomVocabularyTerm` / `VocabularyRescorer`
- Nemotron 専用の `NemotronVocabularyBias.setCustomVocabulary()`

つまり初版で「将来の拡張余地」として L2 に送っていたデコーダ段のバイアスが、**L1 でやれる可能性があります**。

**ただし日本語で機能するかは完全に未検証です。** `ContextBiasingConstants` は
英語ストップワード ("a", "the", "and" ...) 前提の類似度ゲートを持ち、`itnDefaultConfig` も英語ブランド名を想定しています。
ここは実測してから採否を決めます。

そのため辞書は 2 層で設計し、上の層が日本語で効かなければ下の層だけで成立するようにします。

- **L1: 語彙バイアス** — FluidAudio の `VocabularyBoostingSession`。効けばデコード段で正しく効く
- **L2: 読み一致置換 (必ず実装)** — 確定テキストをカタカナ読みに正規化し、辞書の読みと編集距離で照合して置換。
  「オルカ」→「Orca」、「エヌエスパネル」→「NSPanel」。**L1 が日本語で不発でもこれだけで成立する**

辞書エントリは `表記` / `読み` / `スコープ` を持ちます。
リポジトリ固有の語彙 (クラス名など) を全環境に効かせると誤爆するため、スコープは必須です。

現在の採用エンジンである Apple `SpeechTranscriber` には語彙バイアスの公開 API がないため、
L1 は Apple では使えません（[02 音声エンジン](02-speech-engines.md)）。

### 日本語の後処理 — 既存実装の不具合がそのまま要件リストになる

VoiceInk の CJK 関連 issue が、実装前に潰しておくべき項目を教えてくれます。すべて既に踏まれた地雷です。

| 現象 | 出典 | 対策 |
|---|---|---|
| 自動付与される末尾スペース | VoiceInk #270 | CJK 判定して抑止 |
| 非分かち書き言語で単語置換辞書が動かない | VoiceInk #227 | 上記 L2 を読み単位で実装 (単語境界に依存しない) |
| 非英語モードで初期プロンプトが言語追従せずローマ字化 | VoiceInk #893 | プロンプトをロケール連動に |
| 日本語から英語へ勝手に切り替わる | VoiceInk #182 | 言語を固定し auto-detect を使わない |
| 無音時の「ご視聴ありがとうございました」型 hallucination | Vibe #620 / OpenWhispr #462 | Whisper 系を使わないので原理的に回避。VAD で無音を投入しない |
| CJK 前後の空白・約物の乱れ | OpenSuperWhisper の `asian-autocorrect` | 同等の整形パスを持つ |

加えて **モデル × 言語の非対応組み合わせを起動時に弾くゲート**を実装します。
`anomalyco/hex` が `supports_language` / `validate` で `bail!` する設計を持っており、
逆に Hex (Swift) はゲートを持たないため既定 Parakeet v3 のまま日本語を選べてしまう不整合を抱えています。
**Parakeet v3 の日本語 CER は 159% なので、これは無音ではなくゴミが出る事故になります。**

### 実機で出た辞書の必要性（2026-09-04）

利用者が音声入力そのもので報告: **「末尾」と言うと「松尾」になる。**
開発用語（末尾・尾びれ）が人名に化けるのは、固有名詞側の言語モデルが強いためです。

- Apple `SpeechTranscriber` の語彙バイアス API は**ドキュメント上見つかっていない**
- したがって **L2（確定テキストをカタカナ読みに正規化し、辞書の読みと編集距離で照合して置換）が唯一の手段**になる。
  「マツオ」→「末尾」のような、読みが同じで表記が違う語の置換がまさにこの用途
- **形態素解析の併用**: 読み一致だけだと「松尾さん」のような正しい人名も壊す。形態素解析で品詞と文脈（直後が「さん」なら人名、
  「に」「が」なら普通名詞）を見て適用を絞れる。ただし辞書サイズと遅延が乗るので、
  **まず L2 の素朴な読み置換を作り、誤爆が実際に出たら形態素解析を足す**（順序は変えない）

## 訂正

R6 の「喋りながら違和感を覚えたら直す」は、**確定済みテキストの直近部分を編集可能に保つ**ことで実現します。

- 確定セグメントの語はクリック可能。クリックで候補ポップオーバー（同音候補 + 辞書候補）。
- `⌃Z` で直前の確定セグメントを訂正モードに入れる。手を離さずキーボードだけで完結できること。
- 訂正した語はそのまま辞書登録の候補として提示する。ここが辞書との接続点で、
  同じ誤認識を 2 回直したらユーザーが辞書登録に気づく導線になっている。
- 訂正中も録音は止めない。訂正操作と発話を並行できる。

**機能フラグで丸ごと無効化できること (必須)。**
訂正 UI は「喋りに集中したいときには邪魔」という性質を持つので、オフにできる必要があります。

```yaml
features:
  correction: false   # 訂正 UI と候補ポップオーバーを無効化
  dictionary: true    # 辞書による後処理置換は独立して切れる
```

`correction: false` のとき、確定テキストはクリック不可・`⌃Z` は無効・候補計算そのものを走らせない。
候補計算をしないぶん、オフ時は確定レーンの後処理も軽くなります。既定値は実測してから決めます。
