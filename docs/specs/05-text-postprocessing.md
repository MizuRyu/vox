## 辞書

### L1 語彙バイアス（未実装。採用していないエンジンの話）

**初版の訂正: 「CoreML 変換済みモデルには hotword biasing の公開 API が存在しない」は誤りでした。**
FluidAudio に本物の文脈バイアス API が公開されています。

- `configureVocabularyBoosting(vocabulary:ctcModels:config:)`
- `CustomVocabularyContext` / `CustomVocabularyTerm` / `VocabularyRescorer`
- Nemotron 専用の `NemotronVocabularyBias.setCustomVocabulary()`

つまり初版で「将来の拡張余地」として L2 に送っていたデコーダ段のバイアスが、**L1 でやれる可能性があります**。

**ただし日本語で機能するかは完全に未検証です。** `ContextBiasingConstants` は
英語ストップワード ("a", "the", "and" ...) 前提の類似度ゲートを持ち、`itnDefaultConfig` も英語ブランド名を想定しています。
ここは実測してから採否を決めます。

そのため辞書は 2 層で設計し、上の層が日本語で効かなければ下の層だけで成立するようにしました。

- **L1: 語彙バイアス** — FluidAudio の `VocabularyBoostingSession`。効けばデコード段で正しく効く
- **L2: 認識後の置換（必ず実装）** — 確定テキストの表記を辞書で置き換える。
  「オルカ」→「Orca」、「エヌエスパネル」→「NSPanel」。**L1 が日本語で不発でもこれだけで成立する**

現在の採用エンジンである Apple `SpeechTranscriber` には語彙バイアスの公開 API がないため、
L1 は Apple では使えません（[02 音声エンジン](02-speech-engines.md)）。上の FluidAudio の API は
確定レーンを入れ替える判断をしたときに再評価します。

### L2 表記置換（実装済み）

照合は**表記の完全一致**で、読みの正規化と編集距離は使いません（[ADR-019](../adr/019-dictionary-surface-replacement.md)）。
辞書エントリは `認識される表記` / `入れたい表記` の 2 列だけで、`読み` と `スコープ` は持ちません。
リポジトリ単位で語彙を切り替える設計（スコープ）は L2' と同じく未実装です。

| 項目 | 決めたこと |
|---|---|
| 保存先 | `~/Library/Application Support/vox/dictionary.tsv`（0600、上限 64KiB） |
| 書式 | 1 行 = `認識される表記<TAB>入れたい表記`。`#` で始まる行と空白だけの行は無視。右辺が空なら削除 |
| 照合 | Character 単位の完全一致。最長一致で、左辺が重複する行は最初の行だけを採る。置換した結果は再走査しない |
| 正規化 | しない（大小・全半角・読み）。表記の揺れは行を足す |
| 順序 | 辞書 → フィラー除去（`CommittedText.clean`）。逆順だとフィラーと同じ音で始まる誤認識の頭が先に削られる |
| 適用範囲 | 音声由来の確定差分（`committed` の追記分）だけ。`tentative`・手入力・履歴の `raw_text` には掛からない |
| 読み込み | 録音開始時に 1 度。録音中にファイルを変えてもその回には効かない |
| 壊れた行 | その行だけ落として続行し、設定画面が 1 始まりの行番号で知らせる。直すのはエディタ |
| 編集 | 設定画面の表（「認識される表記」「入れたい表記」）で追加・編集・削除する。セルの確定（Enter またはフォーカスを外す）ごとにファイルへ書く（[ADR-021](../adr/021-dictionary-edited-in-settings.md)） |
| 表に出ない行 | コメント・空行・壊れた行は元の位置と元の文字列のまま残す。表の行は元の位置で書き換え、新しい行は末尾に足し、削除は行ごと消す（`DictionaryDocument`） |
| 書かない編集 | 左辺が空の行（打ち込み途中として画面に残す）、既にある左辺、タブ・改行を含む表記と `#` で始まる左辺、64KiB を超える内容。読んだ後にファイルが外で変わっていたら書かずに読み直す。保存できなかった値は画面に残す（`DictionaryRows`） |
| 書き方 | 同じフォルダの一時ファイル（0600）に書き切ってから名前を置き換える。書き込みに失敗しても元のファイルは残る |
| 切り方 | ファイルを退避するか行頭に `#` を付ける。専用の機能フラグは持たない |

受け入れている制約: 短い左辺は無関係な場所でも当たる（「松尾」→「末尾」は「松尾さん」も壊す）。
確定差分の境界をまたぐ語は当たらない。

辞書自身は畳みをしません。右辺を空にして語を消した跡の読点は、後段のフィラー除去が 1 つに畳みます
（`--no-filler-removal` の回はそのまま残ります）。

### 日本語の後処理 — 既存実装の不具合がそのまま要件リストになる

VoiceInk の CJK 関連 issue が、実装前に潰しておくべき項目を教えてくれます。すべて既に踏まれた地雷です。

| 現象 | 出典 | 対策 |
|---|---|---|
| 自動付与される末尾スペース | VoiceInk #270 | CJK 判定して抑止 |
| 非分かち書き言語で単語置換辞書が動かない | VoiceInk #227 | 上記 L2 を単語境界に依存しない最長一致で実装（ADR-019） |
| 非英語モードで初期プロンプトが言語追従せずローマ字化 | VoiceInk #893 | プロンプトをロケール連動に |
| 日本語から英語へ勝手に切り替わる | VoiceInk #182 | 言語を固定し auto-detect を使わない |
| 無音時の「ご視聴ありがとうございました」型 hallucination | Vibe #620 / OpenWhispr #462 | Whisper 系を使わないので原理的に回避。VAD で無音を投入しない |
| CJK 前後の空白・約物の乱れ | OpenSuperWhisper の `asian-autocorrect` | 同等の整形パスを持つ |

加えて **モデル × 言語の非対応組み合わせを起動時に弾くゲート**を実装します。
`anomalyco/hex` が `supports_language` / `validate` で `bail!` する設計を持っており、
逆に Hex (Swift) はゲートを持たないため既定 Parakeet v3 のまま日本語を選べてしまう不整合を抱えています。
**Parakeet v3 の日本語 CER は 159% なので、これは無音ではなくゴミが出る事故になります。**

### 実機で出た辞書の必要性（2026-09-04）

利用者が音声入力そのもので報告: **「末尾」と言うと「松尾」になる。**
開発用語（末尾・尾びれ）が人名に化けるのは、固有名詞側の言語モデルが強いためです。

- Apple `SpeechTranscriber` の語彙バイアス API は**ドキュメント上見つかっていない**
- したがって **L2（確定テキストの置換）が唯一の手段**になる。「松尾」→「末尾」のように、
  聞こえた表記を書きたい表記へ置き換えるのがまさにこの用途（実装した方式は [ADR-019](../adr/019-dictionary-surface-replacement.md)）
- **形態素解析の併用**: 表記一致だけだと「松尾さん」のような正しい人名も壊す。形態素解析で品詞と文脈（直後が「さん」なら人名、
  「に」「が」なら普通名詞）を見て適用を絞れる。ただし辞書サイズと遅延が乗るので、
  **まず L2 の素朴な表記置換を作り、誤爆が実際に出たら形態素解析を足す**（順序は変えない）

## 訂正

状態: **未実装**。辞書候補の自動提案も含めて入れないと決めました（[ADR-019](../adr/019-dictionary-surface-replacement.md)。
差分の取得・候補の保存・提示 UI が一式必要で、辞書そのものより大きい）。見直しの条件は ADR-019 にあります。
以下は当時の設計です。

R6 の「喋りながら違和感を覚えたら直す」は、**確定済みテキストの直近部分を編集可能に保つ**ことで実現します。

- 確定セグメントの語はクリック可能。クリックで候補ポップオーバー（同音候補 + 辞書候補）。
- `⌃Z` で直前の確定セグメントを訂正モードに入れる。手を離さずキーボードだけで完結できること。
- 訂正した語はそのまま辞書登録の候補として提示する。ここが辞書との接続点で、
  同じ誤認識を 2 回直したらユーザーが辞書登録に気づく導線になっている。
- 訂正中も録音は止めない。訂正操作と発話を並行できる。

**機能フラグで丸ごと無効化できること (必須)。**
訂正 UI は「喋りに集中したいときには邪魔」という性質を持つので、オフにできる必要があります。

```yaml
features:
  correction: false   # 訂正 UI と候補ポップオーバーを無効化
  dictionary: true    # 辞書による後処理置換は独立して切れる
```

`correction: false` のとき、確定テキストはクリック不可・`⌃Z` は無効・候補計算そのものを走らせない。
候補計算をしないぶん、オフ時は確定レーンの後処理も軽くなります。既定値は実測してから決めます。

実装した辞書の切り方はこの YAML ではなく、辞書ファイルの有無と `#` によるコメントアウトです（ADR-019）。
