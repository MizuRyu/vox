# 04 コマンドパレット

録音を止めずに開くパレット、sigil によるソース切替、検索対象フォルダの解決と切り替え。

最終確認日: 2026-09-23

音声供給の一時停止は廃止しました。パレットを開くときは未確定部分の確定処理だけを別タスクで行い、
モデル・セッション・音声供給を維持します。パレット表示中の発話も通常どおり本文に反映します。

## sigil によるソース切替

パレットは「ファイル選択 UI」ではなく **発話中のコマンドパレット**として設計します（[ADR-005](../adr/005-command-palette-sigil.md)）。
単一ホットキー `⌃P`（変更可）で開き、先頭の記号でソースを切り替えます。HUD に `@` を打つ方法もあります。

| sigil | ソース | v1 |
|---|---|---|
| `@` | リポジトリ内のファイルパス | **実装する** |
| `#` | シンボル / 関数名 / クラス名 | 拡張 |
| `!` | 定型コマンド・スニペット | 拡張 |
| `~` | git ブランチ名 | 拡張 |
| `%` | クリップボード履歴 | 拡張 |

**v1 で実装するのは `@` だけです。** ただし**ソースを差し替え可能なインターフェースとして最初から作ります**。
理由は、後から足すのが難しいのは実装ではなく**指が覚えた操作**だからです。
sigil 方式なら、ソースを何個足してもホットキーが増えず、筋肉記憶も壊れません。

sigil の割り当てを設定画面で変更する機能は未実装です。
フォルダ選択モードでは検索フィールドの記号を `~` で表示しますが、sigil の割り当ては変えていません
（`~` を打ったときのソースは従来どおり拡張予定のブランチです）。

## 流れ

1. **`⌃P` または `@`** — パレットを開き、`SpeechLane.finalizeSegment()` を別タスクで実行する。音声供給は止めない。
2. **対象の解決** — 録音開始時の前面アプリをもとに検索対象を解決する。取得できなければ `--repo` を使う（下記）。
3. **検索とプレビュー** — 左に候補、右にプレビューを表示する。クエリが空なら変更ファイルを優先し、入力があれば fuzzy match で絞る。プレビューは選択・コピーでき、ヘッダのボタンで表示中のプレビューテキストをまとめてコピーできる。
4. **`Enter`** — 開いた時点の確定処理を待ち、本文末尾にパスを挿入する。`@` を `head` の途中に打った場合だけ、その位置に挿入する。
5. **閉じる** — HUD にキーフォーカスを戻す。`esc` はパスを挿入しない。音声供給の再開処理は不要で、状態表示は「録音中」のまま。

## 検索対象の解決

検索対象は「トグル ON 時の前面アプリ」から導きます（R15、[ADR-011](../adr/011-hud-edit-mode-and-context-cwd.md)）。

- **Orca が前面のとき** — Orca の画面でアクティブなローカル worktree を検索対象にする。
- **ターミナルが前面のとき** — その cwd を含むリポジトリを検索対象にする。
- **一意に決まらないとき** — `--repo` で指定した検索フォルダを使う。

### 同一リポジトリの別 worktree

現在の検索対象が Git worktree の場合、同じリポジトリにある別の worktree を自動で調べます。
候補はクエリが空の Changes 表示でファイル行の前に並び、`worktree` バッジが付きます。
候補を選ぶとパスを挿入せず、その worktree に検索対象を切り替えて索引を読み直します。
検索中と Tree 表示には候補を出しません。

## 検索対象の切り替え

自動で解決したフォルダ以外も検索対象にできます。導線は 2 つで、どちらもパスを挿入せず対象だけを切り替えます。

### 最近使ったフォルダ（既定の導線）

パレットからファイルを確定した回に、そのときの検索対象を最近使ったフォルダとして記録します。
開いただけでは記録せず、自動で解決したフォルダ（Orca / ターミナル / `--repo`）も同じ扱いで記録します。
保存先は `~/Library/Application Support/vox/folders.json`（上限20件。溢れたら最後に使った時刻が古い順に落とし、
読み込み時に消えたフォルダを落とします）。

候補はクエリが空の Changes 表示で worktree 候補の後・ファイル行の前に最大3件並び、`フォルダ` バッジが付きます。
今の検索対象は候補に出しません。履歴が空のときは候補を出さないので、見た目は従来と同じです。
検索中と Tree 表示には候補を出しません。

### フォルダ選択モード

ヘッダの検索対象パスをクリックするとフォルダ選択モードに入ります。候補は最近使ったフォルダだけになり、
検索フィールドの記号が `~`、打った文字でフォルダを絞り込みます。ファイル行と貼り付け先の表示は出しません。
Tree 表示から入ったときは Changes に戻します（描くのがファイル行のまま選ぶのがフォルダになるのを避けるため）。
最後の行の「フォルダを選ぶ」から `NSOpenPanel`（`canChooseDirectories` のみ）で履歴に無いフォルダを指定できます。
パネルを出すときも `NSApp.activate` は呼びません（前面アプリを変えない。ADR-011）。
録音中の `esc` は CGEventTap が飲むためパネルに届かないので、Vox 側で
**フォルダ選択パネル → フォルダ選択モード → パレット**の順に閉じます。
パレットを閉じるときと録音を片付けるときはパネルも閉じ、その後に届いた選択結果は捨てます。

### 巡回キー

`⌘]` で候補（worktree → 最近使ったフォルダの順、最大3件）を 1 つずつ巡り、
最後まで行くと押し始めた検索対象に戻ります。パスは挿入せず、切り替えだけを行います。
候補が無いときは何も起きません。

輪は**最初の打鍵の時点の候補で写し取ります**。切り替えると今の対象が候補から外れて元の対象が
候補に入るため、押すたびに候補を数え直すと 2 つのフォルダを往復するだけになります。
パレットを開き直したときと、候補行・フォルダ選択から選び直したときに写し直します。
検索中と Tree 表示でも同じ輪を使います（候補行は出ていなくてもキーは効きます）。

`Tab` は HUD のフォーカス移動と衝突するため使いません。`⌘]` を選んだ理由は、
検索フィールドの field editor が持つキー（↑↓ / `Enter` / `⌥Enter`）とメインメニューの項目
（`⌘,` `⌘Q` `⌘Z` `⌘X` `⌘C` `⌘V` `⌘A` `⌘W`）のどちらとも衝突せず、
パネルの `performKeyEquivalent` で確実に受けられるためです。

### 切り替えの寿命

切り替えた対象はその録音の間だけ有効です。パレットを閉じて開き直しても同じフォルダで、
次の録音は再び自動解決から始まります。同じフォルダに固定する設定は持ちません。

計測 JSONL の `palette_target_source` は、自動解決が `orca` / `terminal` / `fallback`、
切り替えた回が `worktree` / `recent`（候補行）/ `manual`（`NSOpenPanel`）です。

## 索引とプレビュー

パレットを開くたびに `FileIndexer.load` で索引を作ります。Git のファイル一覧と変更状態を読み、`.gitignore` を尊重します。
追跡済みのファイルは、後から ignore 対象にしても索引に残ります。Git 管理外では `fd` があれば ignore 設定を反映しますが、
`fd` がない場合の代替処理は `.gitignore` を解釈しません。

### 常駐索引

起動時に `folders.json` のフォルダのうち **Git 管理下のもの**（新しい順に最大20件）の索引をメモリに持ちます。
登録済みのフォルダを開いたときは保持している索引を先に出し、裏で読み直して差し替えます。
未登録のフォルダは今までどおり開くたびに読みます。設定項目も登録画面も持たず、ディスクにも残しません。

更新の契機は FSEvents です。作業ツリーと（linked worktree では作業ツリーの外にある）git ディレクトリを監視し、
イベントが止んでから 500ms 後にまとめて処理します。作業ツリーの変更は `git status --porcelain -z` だけを読み直し、
追跡ファイルの一覧は保ちます。`git ls-files -z` を読み直すのは git ディレクトリの `index` か `HEAD` が動いた回だけです
（`index.lock` や `refs/` の変更では読み直しません）。読み直しの最中に届いた変更は 1 つにまとめて後から処理します。

上限は 20 件 × 1 フォルダ 20,000 件（`fallbackFileLimit`）= 400,000 件です。超えたときは**古い順**に索引を捨て、
そのフォルダは開くたびの読み込みに戻ります。入り切らなかったフォルダより古いものはまとめて捨てます
（並びを飛ばして採らない）。診断ログには読み直しの回数と所要時間だけを出し、パスは `--log-text` の回だけ付きます。

**見直しの条件**: 常駐が実際に使うメモリが上限の想定（400,000 件）を超えて体感に出る場合、または
FSEvents の監視対象が多すぎて読み直しが続く場合は、上限そのものと「既定オン」の判断をやり直します。

プレビューは検索対象内の通常ファイルに限り、最大 64 KiB・40 行です。検索対象外のファイル、シンボリックリンク、
特殊ファイルの本文は開きません。パスの挿入はファイル内容の送信ではありません。

計測は schema 5 の `palette_open_ms`（表示していた時間）を使い、旧 `palette_resume_ms` は廃止しました。
