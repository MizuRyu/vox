# 使い方

Vox の起動、録音、ファイル検索、設定、データ保存と現在の制約をまとめます。必要な環境と最初の起動は [README](../README.md) を参照してください。

## 起動と終了

Applications に置いた `Vox.app` を開きます。起動中は Dock とメニューバーに Vox が表示され、どちらからも設定と終了へ進めます。メニューが見つからないときは `Vox.app` をもう一度開くと、セットアップ画面が開きます。

ウィンドウを閉じても常駐は続きます。アプリ自体を止めるには「Voxを終了」を選びます。「ログイン時に開く」は任意で有効にできます。

ソースからの起動、必要な開発環境、ログの確認方法は [開発手順](development.md) にあります。

## 初回の権限設定

初回はセットアップ画面で、マイク・アクセシビリティ・入力監視を順に許可します。許可済みの項目には緑のチェックが付き、システム設定から戻ると進捗が更新されます。反映されない場合は「状態を再確認」を押し、macOS が再起動を求めた場合は Vox を終了して開き直してください。

<img src="../images/setup.png" alt="3つの権限を番号と緑のチェックで確認する初回セットアップ画面" width="620">

*権限を2項目設定済みとした表示例です。実際の許可状態は起動時に確認します。*

### 更新後に権限が効かなくなったとき

macOS はコード署名の要件でアプリの同一性を判定します。署名 identity が変わった版に入れ替えると、以前のアクセシビリティ・入力監視の許可が無効になります。その場合は Vox を終了し、システム設定の「プライバシーとセキュリティ → アクセシビリティ」で Vox の項目を削除してから、`/Applications/Vox.app` を追加して許可し直し、開き直してください。入力監視も同様です。

## 録音と貼り付け

1. 貼り付けたい入力欄にカーソルを置き、録音キー（既定 `⌘⇧Space`）を押します。
2. 話しながら HUD の本文を確認します。必要なら直接入力・編集し、ファイル検索でパスを挿入します。
3. 録音キーをもう一度押します。本文が確定し、最初に選んだアプリへ貼り付けられます。

HUD の淡色の本文は認識の途中です。一文話して 1 秒ほど間を置くと、そこまでが確定して通常の色になります。間を置かずに話し続けた場合は、これまでどおり認識エンジンの区切りを待ちます。

`Esc` を押すと録音中の本文を破棄します。貼り付け前には元のアプリと、取得できる場合は入力欄を再確認します。入力欄を取得できないアプリでは、同じプロセスかどうかまでの確認になります。クリップボードの受領通知は、相手アプリへの挿入完了や送信完了を保証しません。

HUD にキーフォーカスがあるとき、`⌘V` でクリップボードの画像を取り込めます。画像そのものは貼り付け先へ渡さず、端末内に保存してそのパスを本文へ挿入します。対応形式は PNG・JPEG・HEIC・GIF・TIFF で、1 枚の上限は 32MiB です。クリップボードに文字が同時にある場合は通常のペーストになり、画像ファイルをコピーした場合はコピーを作らずそのファイルのパスが入ります。確定は画像の保存が終わるまで待つため、保存が終わる前に Enter が送られることはありません。保存できなかった場合と対応していない形式の場合は、HUD の下段に理由を1行表示します。

## ショートカット

| キー | 操作 |
|---|---|
| `⌘⇧Space` | 録音開始／確定して貼り付け（既定） |
| `⌃P` または HUD に `@` を入力 | 録音中にファイル検索を開く（既定） |
| パレットで `Enter` | ファイルのパスを本文へ挿入。Tree のフォルダ行では展開／折り畳み、worktree 候補とフォルダ候補では検索対象を切り替え |
| パレットで `⌘]` | 検索対象の候補（別 worktree、最近使ったフォルダ）を順に巡る |
| `Esc` | パレットを閉じる。フォルダ選択モードではファイル検索に戻る。録音画面では本文を破棄 |
| `⌘,` | Vox の HUD や設定画面にフォーカスがあるとき、設定を開く |
| `⌘V` / `⌘C` / `⌘X` / `⌘A` / `⌘Z`（`⌘⇧Z` でやり直し） | HUD の本文を編集（貼り付け・コピー・切り取り・全選択・取り消し）。`⌘V` の画像はファイルに保存してパスを挿入 |

設定画面でキー表示をクリックし、組み合わせを押して「保存」します。⌘・⌃・⌥ のいずれかを含む組み合わせ、または F1〜F12 を登録できます。録音とファイル検索に同じキーは設定できません。

キーを決める優先順位は、**起動引数、保存設定、既定値**の順です。起動引数で固定したキーは、その起動中は設定画面で編集できません。変更は待機中ならすぐ反映され、録音中なら次の録音から使われます。「初期値に戻す」も保存後に反映されます。

## ファイル検索

録音中に検索キー（既定 `⌃P`）を押すか、HUD に `@` を入力するとファイル検索が開きます。ファイルを選んで `Enter` を押すと、検索対象からの相対パスを本文へ挿入します。パスの挿入はファイル内容の送信ではありません。

`Changes / Tree` で表示を切り替えられます。Changes は変更されたファイルを優先して表示します。Tree は索引済みのファイルを階層表示し、同じ階層ではフォルダを先に並べます。三角ボタンまたはフォルダ行の `Enter` で展開・折り畳み、検索中は一致したファイルの親フォルダを自動で展開します。空フォルダや索引にないファイルは表示しません。

Git 管理下では、追跡されていない ignore 対象を除外します。追跡済みのファイルは、後から ignore 対象にしても索引に残ります。Git 管理外では `fd` があれば ignore 設定を反映しますが、`fd` がない場合の代替処理は `.gitignore` を解釈しません。

![架空のプロジェクトをフォルダツリーで表示したファイルビュー](../images/palette-tree.png)

*実ビューを架空のファイル名と本文で描画した例です。*

検索対象は、録音を開始した時点の前面アプリから決めます。Orca ならその画面でアクティブなローカル worktree、Zed なら最前面のウィンドウで開いているプロジェクト、ターミナル（Terminal.app / Ghostty / cmux / iTerm2 / Warp）なら見ているタブの `cwd` を含むリポジトリです。ターミナルのタブは直前に出力があったものを見ているタブとみなすため、裏のタブでビルドを流しているとそちらが選ばれることがあります。

どれにも当てはまらないアプリが前面のときは、設定済みの検索フォルダ（`--repo`）、次に最近使ったフォルダ、最後にカレントディレクトリを使います。この場合はヘッダのパスが「対象を特定できず」の表示になるので、そのままヘッダから切り替えられます。

現在の検索対象が Git worktree の場合、同じリポジトリにある別の worktree を自動で調べます。候補はクエリが空の Changes 表示でファイル行の前に並び、`worktree` バッジが付きます。候補を選ぶとパスを挿入せず、その worktree に検索対象を切り替えて索引を読み直します。検索中と Tree 表示には候補を出しません。

### 検索対象のフォルダを切り替える

ファイル検索からファイルを確定すると、そのときの検索対象を最近使ったフォルダとして覚えます。開いただけでは覚えません。次からはクエリが空の Changes 表示に、最近使ったフォルダが最大3件、`フォルダ` バッジ付きで並びます。選ぶとパスを挿入せず、そのフォルダに検索対象を切り替えます。履歴がないあいだは候補が出ないので、見た目は変わりません。

ヘッダの検索対象パスをクリックするとフォルダ選択モードに入ります。候補は最近使ったフォルダだけになり、打った文字でフォルダを絞り込みます。履歴にないフォルダは「フォルダを選ぶ」から指定できます。`Esc` は、フォルダ選択パネルが出ていればそれを閉じ、次にファイル検索へ戻ります（パレットは閉じません）。

`⌘]` を押すと候補（別 worktree のあと、最近使ったフォルダ）を順に巡り、最後まで行くと押し始めたフォルダに戻ります。候補の並びは最初に押した時点で決まるので、押し続けても同じ2つを往復しません。検索中や Tree 表示でも同じ候補を巡ります。候補がないときは何も起きません。

切り替えた検索対象はその録音のあいだだけ有効です。パレットを閉じて開き直しても同じフォルダで、次の録音では前面アプリからの自動判定に戻ります。

一度ファイル検索から確定したフォルダ（Git 管理下のもの、最大20件）は、次回の起動から索引をメモリに持ちます。そのフォルダでパレットを開くと候補がすぐに出て、裏で最新の状態に差し替わります。編集やコミットは 0.5 秒ほど遅れて自動で索引に反映します。持てる量には上限があり、超えた分は古いフォルダから外れて、開くたびの読み込みに戻ります。設定項目はありません。

プレビューは検索対象内の通常ファイルに限り、最大 64 KiB・40行です。検索対象外のファイル、シンボリックリンク、特殊ファイルの本文は開きません。

## 設定

設定は、メニューバーの「設定…」、HUD の歯車、Vox にフォーカスがあるときの `⌘,` から開きます。本体が動いていなくても、録音を始めずに設定画面だけを表示できます。

<img src="../images/settings.png" alt="録音キーを Command・Option・Space に変更した設定画面" width="548">

*本体と同じ設定ビューを、合成設定・架空のマイク情報でオフスクリーン描画しています。*

設定は `~/Library/Application Support/vox/settings.json` に保存します。

### 自動 Enter

「貼り付け後にEnterを押す」をオンにして保存すると、次の録音から有効になります。既定はオフです。送り方は選びません（[ADR-014](adr/014-auto-enter-readability-decides.md)）。

- 入力欄を読み返せるアプリでは、本文・カーソル・入力先が一致した場合だけ Enter を送ります。
- 読み返せないアプリ（ターミナルなど）では、「ターミナルでもEnterを押す」をオンにした場合だけ、貼り付けから 0.5 秒以上待ち、同じアプリ・ウィンドウであれば Enter を送ります。オフのままなら送りません。以前「貼り付け後に送る」を選んでいた設定は、この項目のオンとして自動で引き継ぎます。

どちらの場合も、修飾キーが離されるまで期限内で待ちます。押されたままの場合、入力先が変わった場合、クリップボードが競合した場合は Enter を省略します。確定待ち中に `Esc` を押すと Enter だけを取り消せます。

読み返せないアプリでは、同じウィンドウ内のタブや入力先の変更までは判別できません。アプリによっては Enter が送信やコマンド実行になるため、最初は送信の起きない入力欄で確認してください。

### 辞書

よく誤認識される表記を、入れたい表記に置き換えられます。設定画面の「辞書」の表に、「認識される表記」（音声認識が出す表記）と
「入れたい表記」（本文に入れたい語）を 1 行ずつ入れます。「追加」で空の行を足して打ち込み、Enter を押すか別の欄に移ると保存します。
行を選んで「削除」を押すと消えます。左の列が空の行は保存せず、既にある表記を入れると「「<表記>」はすでにあります。」と出ます。
保存できなかった値は表に残り、ほかの行を保存しても「保存していない行があります。」と出続けます。直してから Enter を押すと保存し直します。

中身は `~/Library/Application Support/vox/dictionary.tsv` に保存します。「辞書ファイルを開く」でエディタでも編集でき、
1 行に「認識される表記」、タブ、「入れたい表記」を書きます。エディタで変えた後は「更新」を押してから表を編集してください。

```
松尾	末尾
オルカ	Orca
```

- `#` で始まる行と空行は無視します。表で編集しても、ファイルのコメント行・空行・読み込めない行は元の位置に残ります。右側を空にすると、その語を削除します（フィラー除去が消さない語を自分で消せます）。
- 同じ位置に複数の行が当たるときは、認識される表記が長い行が勝ちます。置き換えた結果をもう一度置き換えることはしません。
- 表記はそのまま照合します。大文字・小文字や全角・半角は区別するので、揺れがあるときは行を足してください。
- 音声で認識した本文にだけ効きます。ファイル検索で入れたパスと、HUD に自分で打った文字は置き換えません。
- **認識される表記が短いと、関係のない場所でも置き換わります。**「松尾」→「末尾」を入れると「松尾さん」も変わります。
  困ったときはその行を消してください。
- 辞書は録音のたびに読み込みます。保存した変更は次の録音から反映されます。
- 読み込んだ件数と、読み込めなかった行番号は設定画面に出ます。「更新」で読み直せます。
  タブの代わりに空白で書いた行は読み込めません。読み込めない行は表に出ないので、エディタで直してください。
- 表計算アプリで開いて保存すると形式が変わることがあります。テキストエディタで編集してください。
- 辞書を使わないときは、ファイルを別名に移すか、行頭に `#` を付けます。

置き換えは貼り付ける本文にだけ適用し、履歴に残る認識結果（`raw_text`）は置き換える前のままです。

### マイクと実験的な音声処理

「使用するマイク」で Vox の録音に使う入力を選び、保存します。macOS 全体の入力・出力設定は変わりません。録音中に保存した変更は次の録音から反映されます。

| 選択 | 動作 |
|---|---|
| 自動（既定） | macOS の既定入力・出力がともに Bluetooth 系で出力が使用中なら、内蔵マイクを使う。内蔵マイクがない場合や、それ以外の組合せでは既定入力を使う |
| macOSの既定 | 録音の準備時点で macOS の既定になっている入力を使う |
| マイク名 | 指定したマイクを使う。未接続なら録音を開始せず、接続または選び直しを案内する |

古い設定も「自動」として読み込みます。設定ファイルの `microphone_input` は `{"mode":"automatic"}`、`{"mode":"system_default"}`、または `{"mode":"device","uid":"機器のUID"}` です。機器の指定は画面で保存できます。

macOS の既定入力と接続中の入力デバイスも表示します。設定を開くたびに取得し、接続後は「更新」でも確認できます。接続方式（「内蔵」「Bluetooth」「USB」など）のラベルが付き、分類できない方式には付きません。一覧のチェックは macOS の既定入力を示します。録音で実際に選んだマイクは診断ログの `audio_input` で確認できます。

通常録音は選んだマイクだけを開き、Vox から音を再生しない構成で動作します。そのため、Bluetooth ヘッドホンで再生中に「自動」が内蔵マイクを選んだ場合、ヘッドホンは音楽用の接続のまま保たれます。マイクに入った音楽を消す機能ではありません。機器ごとの再生継続と認識精度は実機確認が必要です。

「通話向けの音声処理（実験的）」は、Apple のエコー除去・ノイズ抑制を使います。既定はオフで、保存後の次の録音から反映されます。この経路は入力と出力の両方を使い、既定以外のマイクを選ぶと録音が止まる場合があります。再生中の音楽自体が小さくなる場合があるため、再生音量を保ちたい場合はオフにしてください。自動音量低下を最小にしても無効にはなりません。音楽と他人の声を完全には分離できません。[Apple の音声処理の説明](https://developer.apple.com/videos/play/wwdc2023/10235/)

原因を切り分ける場合は、メニューバーで「音声診断を記録（音声は保存しません）」をオンにしてから普段どおり録音し、「診断ログを開く…」で確認します。変換前のチャンネル数、形式、音量の集計だけを1録音につき最大16回記録します。音声サンプルや本文は保存せず、オンにするだけでは録音しません。

## データ保存と現在の制約

確定本文は端末内の履歴に保存します。診断ログへの本文出力は既定でオフになっており、`--log-text` を指定した場合だけ有効です。保存先は [開発手順](development.md#データの場所) に記載しています。

最近使ったフォルダは `~/Library/Application Support/vox/folders.json` に最大20件保存します。ファイル検索を開くたびに読み込み、消えたフォルダは候補から落とします。起動時にも 1 度読み込み、Git 管理下のフォルダの索引をメモリに持ちます（索引はディスクに残しません）。

HUD に貼った画像は端末内の `attachments` フォルダに保存し、起動時に作成から 7 日を過ぎたものと、残りが合計 500MiB を超える古いものを削除します。画像そのものは履歴・計測・診断ログに残しません（`--log-text` を指定した場合も、残るのは本文に入った保存先のパスまでです）。削除された後に本文へ挿入したパスを開いても画像はありません。

認識エンジンは Apple の `SpeechTranscriber` だけで、本体からの切り替えは入れていません（判断は ADR-018）。
