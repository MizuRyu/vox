# ADR-027: 貼り付けた後も確定本文をクリップボードに残す（既定オン、設定で戻せる）

- 状態: **提案**（2026-10-18）
- 関連: [ADR-009](009-text-insertion-promise-pasteboard.md)（promise pasteboard と復元）、[ADR-014](014-auto-enter-readability-decides.md)（自動 Enter の所有権確認）、[ADR-024](024-no-notice-after-commit.md)

## 文脈

利用者の要望（2026-10-18）は「喋った内容をクリップボードに残してほしい。たまに残らないのが困る」。

[ADR-009](009-text-insertion-promise-pasteboard.md) は、Cmd+V の post から 400ms（Chromium / Electron 系は 1500ms）後に貼る前の中身へ戻す。
戻すのは changeCount が動いておらず、読み返しが置いた文字数と一致する回だけなので、残るかどうかが回によって変わっていた（「たまに残る」）。
さらに本文には `org.nspasteboard.ConcealedType` を付けるので、クリップボード履歴のアプリは本文を記録しない。

## 判断

1. **設定「確定した本文をクリップボードに残す」を足す。既定はオン。** 古い設定ファイル（キーが無い）もオンとして読む
2. **オンの回は、復元の代わりに本文を印なしの実データで置き直す。** 時点は復元と同じ（Cmd+V の post から猶予の後、自動 Enter の判定が終わった後）。
   印を外すのを先にすると、履歴のアプリが本文を読んだ時点で受領証が立ち、軸 A の終点が Cmd+V より前になる（[ADR-009](009-text-insertion-promise-pasteboard.md) の実測）。自動 Enter はクリップボードの所有を確かめながら待つので、判定中に置き直すとその確認も崩れる
3. 置き直す条件は復元と同じにする。changeCount が動いていたら（ほかのアプリや次の挿入が書いた）触らない。読み返しが置いた文字数と食い違ったら触らない
4. 受領証が来なかった回は、誰も読んでいないので、その場で印を外して置き直す
5. オフの回は今の動作（貼る前の中身へ戻す）のまま

## 却下した案

- **既定をオフにする**: 利用者の要望は「残す、オフにもできる」。オフが既定だと要望の挙動を得るのに設定が要る
- **最初から印を付けずに置く**: 上の 2 の理由で受領証と自動 Enter の確認が崩れる
- **復元だけ止めて印は残す**: クリップボードには残るが履歴のアプリには残らない。「たまに残らない」の一部（履歴から取れない）が直らない

## 結果として受け入れるもの

- オンの間、貼る前にクリップボードにあった中身は戻らない
- 本文はクリップボード履歴のアプリに記録される。履歴のアプリが同期する設定なら、ほかの端末にも渡る

## 見直しの条件

- 置き直しの後に、遅れて読むアプリで本文が欠ける事例が出たとき（猶予を延ばすか、印を外すだけの方式を検討する）
- 本文が履歴のアプリに残ることが問題になったとき（印を外すかどうかを別の設定に分ける）
