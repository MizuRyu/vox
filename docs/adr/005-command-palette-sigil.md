# ADR-005: 発話中の操作はコマンドパレット。単一ホットキー + sigil でソースを切り替える

- 状態: **承認**
- 日付: 2026-09-01
- 関連: 設計書 §0 決定 6、§5

現在の操作は末尾の「2026-09-05 改訂」を参照。以下の初版には旧ホットキーと音声供給停止の判断が残っている。

## 文脈

当初は「ファイルパスを差し込む」機能だったが、ユーザーから「ファイル以外の操作にも広げたい」と要望。
シンボル名、git ブランチ、クリップボード履歴、スニペットなどが同じ枠に入る。
参照 UI の検索フィールドに `@` が置かれていたのは sigil 設計の示唆だった。

## 判断

**単一ホットキー `⌃K` でパレットを開き、先頭の記号でソースを切り替える。**
`@` ファイル / `#` シンボル / `!` コマンド / `~` ブランチ / `%` クリップボード。
v1 で実装するのは `@` だけだが、**ソースを差し替え可能なインターフェースとして最初から作る**。
sigil の割り当ては settings で変更可能にする。

## 理由

後から足すのが難しいのは実装ではなく**指が覚えた操作**。ホットキー体系は最初に決める必要がある。
sigil 方式なら、ソースを何個足してもホットキーが増えず、筋肉記憶を壊さない。VSCode / Slack の既存の慣習に乗れる。

## 却下した案

| 案 | 却下理由 |
|---|---|
| 操作ごとに別ホットキー | ホットキー空間がすぐ枯渇し、他アプリとの衝突リスクがソースの数だけ増える |
| 音声コマンドで起動（「ファイル」と言う） | 認識精度に依存し誤発と取りこぼしが起きる。「ファイルを読む」のような普通の発話と区別できない。補助手段にはなり得るが主軸にしない |

## パレットの中身（既定表示）

クエリが空のときは `git status` の変更ファイルを出す。「このファイルの〜」と言いたくなる対象はたいてい今触っているファイルなので、無入力で最短距離に来るのが正しい。右ペインにプレビューを付け、同名ファイルの選び間違いを防ぐ。

## 「遅延なく再開」の実体

パレットを開いても **モデルとセッションは捨てない**。止めるのは音声供給だけ。0.6B モデルの ANE ロードは数百 ms〜秒単位かかるので、開くたびにセッションを捨てると必ず間が生まれる。再開時はパレット操作中の音声（キー打鍵音）を破棄し、エンコーダ状態だけリセットする。

## 見直しの条件

- ソースが 6 種類以上に増え、記号の記憶が負担になったとき → sigil の一覧をパレット内に常時表示する（体系は変えない）

## 2026-09-05 改訂 — パレット表示中も録音を続ける

利用者の要望により、パレット表示中の音声供給停止を廃止した。
開いた時点の未確定部分は `finalizeSegment()` で締めるが、モデル・セッション・音声供給は維持する。
検索しながら話した分も本文に入り、選んだパスは閉じる時点の末尾に入る。本文途中で `@` を打った場合はその位置を保つ。

パレットの既定キーは `⌃P`（`--palette-key` で変更可）。HUD に `@` を打っても開く。
起動スクリプトでは `⌃K` を録音の開始・確定に使う。プレビューは選択・コピーできる。
旧 `palette_resume_ms` は廃止し、schema 5 の `palette_open_ms` で表示時間を記録する。

この改訂のコードは反映済み。T22 の完了判定と実機確認の結果は未記録。
`~` は初版のブランチ用 sigil と T23 のフォルダ選択モードで重なるため、T23 実装時に適用範囲を整合させる。
