# ADR-010: 「速さ」の看板指標を発話終了→挿入完了に移し、速報エンジンは Apple にする

- 状態: **承認**（ユーザー判断 2026-09-02 06:50）
- 日付: 2026-09-02
- 関連: 設計書 §0 決定 3・10・11、ADR-001、ADR-007、M0 測定記録（非公開）追記 06:45

## 文脈

決定 3 は当初「初出遅延（発話開始から最初の文字が出るまで）合格 400ms / 許容 600ms」だった。
M0 で測定可能な全候補を実測した結果、**どれも満たさなかった**。

| エンジン | 初出遅延 | 根拠 |
|---|---|---|
| Apple `SpeechTranscriber` + `.fastResults` | 0.78〜1.45s（ファイル給餌）/ 1.53s（ライブ、1 サンプル） | 約 1s 周期の tick 待ち。周期を変える API なし |
| Apple 自然モード（`.fastResults` なし） | 発話中に発火しない（+10.6s、セグメント境界のみ） | ライブマイクでも同じ |
| Nemotron @560ms | 0.74〜1.5s | 560ms チャンク床 + 処理 |

## 判断

1. **「速さ」の看板指標を軸 A（発話終了 → 挿入完了）に移す。** 合格 300ms / 許容 500ms。M1 で実測してから数値を確定する
2. **初出遅延は非看板の要件に格下げし、実力に合わせる。** 合格 1000ms / 許容 1500ms。最初の 1s は「聞いている」表示で埋める
3. **速報エンジンは Apple `SpeechTranscriber` + `.fastResults`。** Nemotron @560ms はフォールバック
4. 上記 3 により **ADR-001（native Swift）を承認**する

## 理由

**なぜ初出遅延で勝負しないか。** 全候補が 0.74〜1.5s。第三のエンジン（小型 CTC、kodama-ja-streaming 等）は
ANE 非対応・精度劣化・未検証のいずれかで、調査コストに対して 600ms を切る見込みが薄い。ここで粘ると M1 以降が全部止まる。

**なぜ軸 A なら勝てるか。** 商用の主流（Wispr Flow 700ms p99、Aqua 450ms、Willow 200ms）は「発話終了→挿入完了」を
速さの定義にしており、Wispr Flow が公表する内訳はネットワーク 200ms + LLM 整形 200ms + ASR 200ms。
ローカルはネットワークが消え、Apple の finalize は約 75ms、parakeet-ja の確定は約 209ms。
**整形を挟まなければ 300ms 前後を狙える**（推測。M1 で実測）。技術選定調査でも「ローカルが勝てる唯一の軸」と結論していた。

**なぜリアルタイム表示を捨てないか。** 決定 2（速さと発話中操作の両方が売り）は維持する。
初出 1s は「喋った瞬間に文字」ではないが、「喋っている間に文字が出続ける」（毎秒更新）は成立している。
Superwhisper はこれをクラウドモデル限定にしており、**ローカルで発話中表示ができる**こと自体が差別化のまま残る。

**なぜ Apple か。** 初出遅延は Nemotron と同等だが、CER（疑似音声で 0.158 / 0 / 0 vs 0.05〜0.13）、
待機メモリ（プロセス外 vs 約 142MB）、volatile→final の上書きが OS 実装済み、の 3 点で優位。
`.fastResults` が必須である点は ADR-007 と設計書 §4 に記録した。

## 却下した案

| 案 | 却下理由 |
|---|---|
| 400/600 を維持して第三のエンジンを探す | 上記。見込みが薄く M1 が止まる |
| 基準だけ 1000/1500 に緩める（看板は動かさない） | 「速さが売り」の主張が弱くなる。軸 A を看板にすれば主張を維持できる |
| リアルタイム表示を捨てて push-to-talk に戻る | 決定 2・4 を覆し、看板機能（発話中のパレット）も失う |
| 速報を Nemotron にする | 遅延で差がなく、CER・メモリで劣る。ANE 内で 0.6B を常駐させる分のコストも乗る |

## 結果として受け入れるもの

- 発話開始から約 1s は文字が出ない。UI でこの間を埋める設計が必要（M1）
- 軸 A の 300/500ms は M1 の実測で外れる可能性がある。外れたら数値を実力に合わせて再改訂する（軸は変えない）
- Apple のモデルは OS 依存。macOS 26 未満では動かず、Apple のアップデートで挙動が変わりうる。Nemotron のフォールバック経路を残す理由

## 見直しの条件

- M1 の実測で軸 A が 500ms を大きく超えたとき → 数値の再改訂。500ms を切れない原因が挿入方式（ADR-009）にあるなら先にそれを直す
- Apple が発火周期を制御する API を公開したとき → 初出遅延の基準を再検討
- 日本語 CER で Apple を明確に上回る ANE 対応ストリーミングモデルが出たとき
