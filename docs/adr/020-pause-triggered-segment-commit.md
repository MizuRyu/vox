# ADR-020: 発話の間（無音）を検出して、そこまでを本体側から確定する

- 状態: **承認**（2026-09-24。REC-13 を実機で確認: 1 回の録音で 4 回区切り、確定までの体感が明確に短くなった）
- 関連: [ADR-002](002-two-lane-transcription.md)（二段構成、確定レーンは未実装）、[ADR-007](007-latency-measurement-method.md)（`finalize` の呼び方）、[仕様 03](../specs/03-architecture.md)、[仕様 04](../specs/04-command-palette.md)

## 文脈

HUD は未確定（淡色）と確定（通常色）を分けて表示する。確定は Apple `SpeechTranscriber` が `isFinal` の結果を返した時だけ起きる。
実機のログでは Apple が自発的に区切る間隔は 11〜25 秒で、短い発話は終了キーまで一度も確定しない。
利用者の体感は「グレーから白になるまでが遅い」。

本体には既に `finalize(through:)` を給餌済み位置で呼ぶ経路（`SpeechLane.finalizeSegment()`）があり、
パレットを開く時にだけ使っている（仕様 04）。ログではこの呼び出しから確定まで約 120 ms で、区切りを頼めば速い。
遅いのは「区切りを Apple 任せにしている」ことによる。

## 判断

**発話のあとに無音が約 700 ms 続いたら、本体が `finalizeSegment()` を呼んでそこまでを確定する。**

- 無音の判定は既存の `AudioLevelTracker`（ノイズ床と発話開始の検出）に「最後に発話レベルを超えた時刻」を足して行う。
  しきい値は発話開始と同じ（ノイズ床 × 4）。新しい VAD は入れない
- 判定そのものは VoxCore の純粋な状態機械（`PauseCommitPolicy`）に置き、以下を全部満たす時だけ 1 回発火する
  1. 前回の区切り（または録音開始）より後に発話があった
  2. 最後の発話から **700 ms** 以上、発話レベルを超えていない
  3. 前回の区切りから **1,500 ms** 以上経っている
  4. 未確定の本文が空でない
- 発火は HUD のレベル更新ループ（66 ms 周期、MainActor）から行い、`finalizeSegment()` は別タスクで走らせる。
  締めが走っている間（`hasPending`）は重ねて呼ばない（同じ analyzer に `finalize` を 2 つ入れない。ADR-007）
- パレットを開く時の締めは今までどおり。両方が同じ `finalizeSegment()` を通り、ログ `segment_finalized` に `reason=pause|palette` を足す
- 700 ms は利用者の判断（2026-09-23）。短くすると読点で区切れて語尾の認識が変わりやすく、長くすると効果が薄い

## 影響

- 一文ずつ間を置いて話すと、文ごとに確定して通常色になる。終了キーを押した時に確定する量が減るので、確定から貼り付けまでの時間も短くなる
- 区切った位置で右側の文脈が切れるため、語尾の認識が僅かに変わりうる。パレットを開く時に既に同じことをしており、新しい種類のリスクではない
- 連続して話す（間が 700 ms 未満）限り、これまでと同じ挙動になる
- 設定項目は増やさない。しきい値は定数で持ち、変える理由が出たら ADR を足す

## 却下した案

- **Apple の自発的な区切りに任せる（現状維持）**: 11〜25 秒は HUD の用途には長すぎる
- **結果の到着間隔で間を推定する**: `.fastResults` の結果は約 1 秒周期で束になって届き、発話の間と区別できない
- **一定周期で `finalize(through:)` を呼ぶ**（VoxM0 の定期 finalize と同じ）: 発話中に区切ると単語の途中で切れて誤認識が増える。M0 では計測のための手段であって HUD の挙動には向かない
- **無音のしきい値を設定にする**: 効果と副作用の釣り合いを利用者が調整する材料（実測）がまだ無い

## 見直す条件

- 確定レーン（ADR-002）を入れる時。発話区切りは確定レーンの投入単位でもあるので、同じ判定を共有するか決め直す
- 区切りが原因の誤認識が実機で目立つ時（履歴の `raw_text` と比べて語尾が変わる）。しきい値の変更、または発火条件の追加（例: 未確定本文が句読点で終わる時だけ）を検討する
- Apple が `SpeechTranscriber` に区切りのオプションを公開した時
