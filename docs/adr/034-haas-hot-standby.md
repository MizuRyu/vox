# ADR-034: Haasを先読みし、録音の間もモデルを保持する

- 状態: 承認（2026-11-02の利用者からのホットスタンバイへの変更依頼）
- 日付: 2026-11-02
- 関連: ADR-032のモデル解放方針だけを変更する。モデル・認識経路・設定の選択は同ADRに従う

Haasは確定後60秒の未使用でワーカーを解放していた。同じ取得済みモデルでも、61秒待った後の準備に約1,071msかかった。録音の間隔が空くたびにこの待ちが戻るため、短時間だけの再利用では足りない。利用者はモデルを保持し、録音をすぐ始めることを選んだ。

Haas選択時は、ホットキーを有効にしたあと、取得済みファイルを検証してモデルを先読みする。アイドル中にHaasへ切り替えたときも同じ処理を行う。先読みはダウンロードもマイクの起動も行わない。未取得・検証失敗なら録音開始時の通常の準備に任せる。先読み中に録音が始まった場合は同じ読み込みを待ち、HUDへその段階を伝える。

確定・通常の破棄・待機時間の経過では、正常なワーカーを保持する。音声・認識本文・VADの区間・用語は録音ごとに消す。推論中の破棄でワーカーの停止が必要だった場合は、アイドルに戻ってから取得済みモデルを先読みし直す。Appleへの切り替えとVox終了ではワーカーを解放し、終了後の設定通知では再起動しない。

変更後の2回の単体計測では、61秒待った後のモデル準備は4〜20msだった。先読み完了後の最初の開始は5ms。読み込み自体の時間をVox起動時へ移すため、先読み完了前に録音を始めれば残りの待ち時間は生じる。用語取得・マイク初期化・HUDを含むショートカットから録音開始までの時間を示す値ではない。

待機中のワーカーRSSは約382〜383MiBで、待機300MBの目標を超える。このメモリを使い、繰り返しのモデル読み込みを避ける。Vox全体のphysical footprintや電力の計測値ではない。待機中は認識要求を送らず、モデルを保持する。61秒待機の2回の測定では、ワーカーの累積CPU時間の増分は0.22〜0.25秒だった。

60秒で解放する案は繰り返しの起動待ちが残るため採らない。

## 見直しの条件

日常利用でメモリプレッシャー・発熱・電池消費が問題になった場合は、ワーカーのRSSだけでなくVox全体のphysical footprintとシステムのメモリプレッシャーを測り、保持方針を見直す。モデルを更新した場合も先読み後の開始時間と待機コストを測り直す。
