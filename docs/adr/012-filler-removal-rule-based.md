# ADR-012: フィラー除去は規則ベースの後処理で行い、LLM 整形は入れない

- 状態: **提案**（ユーザー要望 2026-09-02。M2 で実装）
- 日付: 2026-09-02
- 関連: 設計書 §6（辞書と後処理）、ADR-008（正解テキストの規約）、ADR-010（軸 A）

## 文脈

M1 の実測で「フィラーがすごい入る」。Apple `SpeechTranscriber` は「あ、えっと」「なんか」「あの」「うん」「あ、そうそう」を
そのまま文字にする。開発者向け音声入力では、挿入されるテキストにフィラーがあると毎回消す手間が発生し、
「喋ったほうが速い」が成立しなくなる。

商用ツールの多くは LLM 整形でこれを解決している（Wispr Flow は fine-tuned Llama、Hanaseru は日本語特化の整形）。

## 判断

**規則ベースの後処理 `FillerPass` を M2 で入れる。LLM 整形は入れない。**

- 対象は確定テキスト（`committed`）。セグメントの final が届いた時点で適用し、HUD の表示と挿入テキストを一致させる（WYSIWYG）。
  `tentative`（未確定）には適用しない
- ローカル履歴（R17）には**除去前の生テキスト**を残す。除去は挿入用の変換であって、記録を書き換えない
- feature フラグ `features.fillerRemoval`（既定 ON）で丸ごと切れる（設計書 §7 の訂正フラグと同じ扱い）

### 規則（M2 実装時に改訂 2026-09-02）

**改訂の理由**: 実機の出力は `消したいっす。えっとデータ層。` のようにフィラーの後に読点が来ない。
「読点・句点・空白・文頭に接する」を両側に要求すると実用上ほとんど消えず、片側だけにすると「あのファイルを開いて」の連体詞を壊す。
そこで語を 2 群に分けた。

| 群 | 語 | 境界の要求 |
|---|---|---|
| 後続語の一部になりえない | えっと・えーと・えーっと・えー・あのー・うーん・んー | **左側**（文頭・読点・句点・空白）だけ |
| 連体詞・副詞の用法がある | あの・その・まあ | **両側** |

初版の表は下に残す（調整前の意図の記録）。

### 規則（初版）

| 種別 | 例 | 規則 |
|---|---|---|
| 単独フィラー | えっと、えー、えーと、あの、あのー、その、うーん、んー、まあ | 読点・句点・空白・文頭に接する場合のみ除去 |
| 相槌 | うん、はい（文頭）、そうそう | 文頭または読点に挟まれた場合のみ除去 |
| 感動詞 | あ、あー、お、え | 直後に読点があり文頭にある場合のみ除去（「あ、そうそう、」→「」） |
| 言い直しの残骸 | 「なんだっけ」「じゃなくて」 | **除去しない**。意味を持つ可能性があり、誤除去のコストが高い |

除去後に連続する読点・空白を 1 つに畳み、文頭の読点を落とす。

「なんか」は**除去しない**。副詞として意味を持つ用法が多く、誤除去のコストが高い。ユーザーの発話で頻出だが、
辞書（§6）で個別に「なんか、」→「」のような置換をユーザーが登録できるようにする。

## 理由

**なぜ LLM 整形を入れないか。** 軸 A（発話終了→挿入完了）の合格基準は 300ms。Wispr Flow の内訳では LLM 整形だけで 200ms を
専用推論スタック（TensorRT-LLM）で達成している。ローカルの小型 LLM で同等の遅延は見込めず、入れた瞬間に看板指標が崩れる。
また ADR-010 で「整形品質では商用に勝てない、速さで勝つ」と決めている。

**なぜ規則ベースで足りるか。** フィラーの語彙は閉じていて、位置（文頭・読点隣接）で判定できる。誤除去が怖い語（なんか、なんだっけ）を
除外すれば、残りは安全に消せる。Hanaseru も「フィラー除去」を独立機能として売っており、規則で成立する範囲が広いことを示唆する。

**なぜ履歴に生テキストを残すか。** 規則が誤除去したとき、元に戻せる必要がある。除去は可逆でない。

## 却下した案

| 案 | 却下理由 |
|---|---|
| ローカル LLM で整形 | 軸 A が崩れる。ADR-010 の方針に反する |
| Apple の `transcriptionOptions` に頼る | フィラー除去に相当するオプションは見つかっていない（**不明**。あれば規則より優先してよい） |
| `tentative` にも適用 | 未確定テキストは書き換わり続けるので、除去の結果も揺れて視覚的に不安定になる |
| 「なんか」も除去 | 副詞用法を壊す。辞書で個別対応 |

## 結果として受け入れるもの

- 規則から漏れるフィラーは残る。ユーザーが辞書で追加する導線が要る（§6 の L2 と同じ仕組み）
- 「あ、そうそう、」のような相槌の連鎖を消すと文が唐突になることがある。M2 の実測で規則を調整する

## 見直しの条件

- 軸 A の実測に 100ms 以上の余裕があり、かつ規則で 2 割以上のフィラーが残ると分かったとき → 小型 LLM を「非同期の後追い整形」（挿入後に置換）として検討する。挿入前には挟まない
- Apple がフィラー除去のオプションを公開したとき

## 追記（2026-09-08）

除去結果が空白だけになる発話は原文を返す。理由: 「はい」「うん」だけの発話が `empty_text` で失敗していた。
表の例「あ、そうそう、」→「」は規則の説明として残す。
