# ADR-035: 読み返しは自動 Enter を早めるためだけに使い、読めない入力欄より送られにくくしない

- 状態: 承認（2026-11-24 の利用者の承認）
- 日付: 2026-11-24
- 関連: [ADR-014](014-auto-enter-readability-decides.md) の決定 1 を、設定「ターミナルでもEnterを押す」がオンの時だけ変える。[ADR-025](025-terminals-never-read-back.md) の却下案「一致を取れない時は時間切れの後に送る」を、設定がオンの時に限って採る

## 文脈

ADR-014 は、入力欄を読み返せるなら一致した時だけ Enter を送り、読めないなら設定「ターミナルでもEnterを押す」（`auto_enter_unverified`）で決めるとした。
この規則では、設定がオンの時に次の逆転が起きる。

| 入力欄 | Enter |
|---|---|
| 読めない | 貼り付けから 0.5 秒後に送る |
| 読めて、一致する | すぐ送る |
| 読めて、一致しない | 送らない（`timedOut`） |

「読めて、一致しない」は入力の誤りに限らない。貼った本文を組み替えて入れる入力欄では、正しく貼れていても一致しない。
T3 Code（Electron）の入力欄は Tiptap のリッチテキストで、貼り付けを Markdown として解釈し、段落・書式・チップに組み替えてから入れる。
さらに、Electron の入力欄を読めるかどうかは同じ起動の途中で変わった。
実機のログでは、T3 Code を起動し直した直後の 5 回は読めず `postedUnverified` で送られ、途中から読めるようになった後は、修飾キーで省略した 4 回を除く 15 回のうち 14 回が `timedOut` で送られなかった。
利用者からは、設定を変えていないのに自動 Enter が止まったと見える。

ADR-025 はターミナルで同じ逆転を見つけ、アプリの表で避けた。表に行を足す方式は、組み替える入力欄を持つアプリが見つかるたびに 1 行が要る。

未確認: 起動の途中で T3 Code の入力欄が読めるようになった原因。確かめる方法は、T3 Code の起動直後と読めるようになった後で、アプリの `AXManualAccessibility` と入力欄の `AXRole` を読み比べることである。

## 判断

**読み返しは Enter を早めるためだけに使う。読めることで、読めない入力欄より送られにくくしない。**

- 設定がオンの時: 一致すればすぐ送る（`posted`）。一致しない・読めない時は、貼り付けから 0.5 秒待ち、同じアプリ・ウィンドウなら送る（`postedUnverified`）
- 設定がオフの時: ADR-014 のまま。一致した時だけ送る
- 修飾キー・入力先の変更・クリップボードの競合・取り消し・期限による拒否は、どちらでも変えない
- 判定は `AutoEnterGate.run`（VoxCore）。アプリの名前を見ない

設定をオンにした利用者は、確かめずに送ることを受け入れている。読めた結果が不一致でも、読めない時と同じ条件を満たせば送ってよい。
ADR-025 が挙げた却下の理由「一致した時だけ、が崩れる」は、設定がオフの時にだけ当てはまる。

ADR-025 のターミナルの表は残す。設定がオンの時、表は送るかどうかを変えない。設定がオフの時、表があるとターミナルでは一致を待たずに終わり、HUD が 1.5 秒早く閉じる。

## 却下した案

- **組み替える入力欄を持つアプリを表に足す**: 見つかるたびに 1 行が要り、表に無いアプリでは同じ不具合が残る
- **改行・空白を正規化して照合する**: Markdown の記号の除去やチップへの置き換えは、正規化では戻せない
- **期限（1.5 秒）まで一致を待ってから送る**: 一致しない入力欄で毎回 1 秒遅くなる。読めない入力欄は 0.5 秒で送っているので、長く待つ理由がない
- **Vox から Chromium のアクセシビリティを常に有効にする**: 読めても一致しないことは変わらない

## 受け入れる危険

設定がオンの時、読める入力欄で貼り付けの反映が 0.5 秒より遅いと、反映の前に Enter を送る。これまでは一致を最大 1.5 秒待った。読めない入力欄で受け入れている危険と同じ種類である。

## 見直す条件

- 設定がオンの利用者から、読める入力欄で本文より先に Enter が届いた報告が出た時
- ADR-014 の見直しの条件に当たり、設定ごと落とす時
