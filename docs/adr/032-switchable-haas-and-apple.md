# ADR-032: Haas Q4 を既定にし、Apple と認識部分を切り替える

- 状態: **承認**（2026-11-01）
- 一部置換: モデル解放方針は[ADR-034](034-haas-hot-standby.md)に従う
- 置換: [ADR-018](018-no-engine-switch.md)。利用者が日常利用で試し、必要なら Apple に戻す判断による
- 関連: [ADR-020](020-pause-triggered-segment-commit.md)、[ADR-026](026-debug-recording-save.md)、[ADR-031](031-body-transcriber-without-fast-results.md)（廃止）

## 判断

Haas-ja-v1.0 の Q4_K を既定にし、設定の `speech_engine` で `haas` / `apple` を選ぶ。設定のない既存環境も Haas を使う。日常利用で比較するための採用で、Apple を上回る精度かは未確定である。

2026-10-31 の M4・32GB での比較では、Q4 のワーカープロセスのピーク RSS は約 473MiB。約30秒の合成音声を500msごとに更新すると初出は約532ms、入力終了後の確定は約77msだった。保存音声40本の推定 CER は Apple 2.27% / Haas Q4 8.45%、独立した合成音声16本では Apple 8.47% / Haas Q4 4.24% と順位が逆転した。保存音声の正解は Apple 出力から作っており、合成音声も自発発話を代表しない。精度の順位は未確定とする。

`SpeechLane` はマイク入力・形式変換・録音保存・世代管理・確定本文の追記を持ち、認識を `SpeechRecognizer` に委ねる。実装は `AppleSpeechRecognizer` と `HaasSpeechRecognizer` の2つ。HUD、手入力、辞書、フィラー除去、貼り付けは同じ経路を通す。録音開始時に設定を固定し、切り替えは次の録音から反映する。

Haas は speech.cpp v0.10.0 の常駐ワーカーを使う。500ms 間隔で未確定の音声を認識し直し、要求は1件ずつ処理して積み上げない。12秒に達したら直前2秒の静かな位置で区切る。ただし、すでに表示した音声より前へ境界を戻さない。無音・ファイル検索での確定は、その時点までの音声を対象にする。終了時は更新周期を待たず残りを確定する。確定本文は追記専用のまま保つ。

ワーカーの推論・パイプ I/O・ファイル検証は MainActor の外で行う。通常の確定後はモデルを再利用し、60秒の未使用、Apple への切り替え、破棄、終了で解放する。応答の不正・切断・5秒の推論タイムアウトは失敗として扱い、成功に見せない。音声の滞留は30秒を上限とする。失敗時も取得できた音声は保存対象に残し、既存の確定失敗時の本文保護を使う。

## 取得と保存

初回に [speech.cpp v0.10.0 macOS arm64 Metal](https://github.com/nyosegawa/speech.cpp/releases/tag/v0.10.0) と [Haas Q4_K の固定リビジョン](https://huggingface.co/sakasegawa/Haas-ja-v1.0-GGUF/tree/6b965d5007ba780585de51549d57a8c1c0d67c7e) を取得する。配布アーカイブ、展開した実行ファイル、重みの SHA256 をコード内で固定し、検証後だけ起動する。通信は取得だけで、音声も本文も送らない。プロトコルは [worker protocol 4](https://github.com/nyosegawa/speech.cpp/blob/v0.10.0/docs/worker.md) に固定する。SwiftPM の外部依存は増やさない。

録音保存の一般の既定値はオフのまま。オンにした回は認識に渡す PCM 全体を wav に残し、認識の窓ごとには分けない。計測 schema 7 と録音 JSON schema 3 の `speech_model` にモデルを記録する。`segments` は Apple では語ごと、Haas では確定した音声窓の区間であり、Haas の区間を語の時刻として扱わない。7日・500MiB・1録音30分の保存上限、破棄した録音を残さない規則は ADR-026 を維持する。

韻律の試作ツールは語の時刻を使って学習するため、Haas の録音を候補から除く。Haas の語単位の時刻を実装・検証するまで、音声窓の時刻で代用しない。

## 見直す条件

日常利用で認識の欠落・誤り、発熱、終了待ちが気になる場合は、設定で Apple に戻す。保存した同じ音声を両方で認識し直し、問題がモデル・区切り・後処理のどこにあるかを比較する。モデルを更新する場合は、CER に加えて実時間での初出・表示の最大空白・終了待ち・メモリを測り直す。

マイクからの取得、実際の HUD 操作、貼り付けを含む確認は本体を起動できる利用者が行う。合成音声のオフスクリーン再生では実装した両認識器と録音保存を通し、表示が継続することと wav のフレーム数を確認する。
