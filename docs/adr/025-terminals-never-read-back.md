# ADR-025: ターミナルは画面を読めても、自動 Enter の読み返しに使わない

- 状態: **提案**（2026-09-29）
- 関連: [ADR-014](014-auto-enter-readability-decides.md)（自動 Enter は読み返せるかで決める）、[ADR-015](015-palette-target-from-frontmost-app.md)（ターミナルの表）

## 文脈

ADR-014 は「入力欄を読み返せるなら一致を確かめて送る、読めないなら設定『ターミナルでもEnterを押す』で決める」とした。
読み返せるかどうかは「アクセシビリティで何か読めるか」で判定していた。Ghostty は画面全体をテキストとして返すので「読める」側に入るが、貼った本文と「元の入力欄 + 貼った本文」の一致は画面では決して取れない。
実機のログでは Ghostty の自動 Enter 26 回のうち 23 回が `timedOut` で、設定をオンにしていても Enter が送られなかった。

## 判断

**パレットの対象判定でターミナルとしているアプリ（`PaletteTargetAdapter` の `.terminal`: Terminal.app、Ghostty、cmux、iTerm2、Warp）は、何か読めても「読み返せないアプリ」として扱う。** 送るかどうかは設定「ターミナルでもEnterを押す」で決まり、送る時は貼り付けから 0.5 秒待って同じアプリ・ウィンドウなら送る（ADR-014 の読み返せない側と同じ）。

- 判定は `AutoEnterGate.readsBack(bundleIdentifier:)`（VoxCore）。表はパレットと共有し、ターミナルを足す時は表に 1 行
- 設定の名前「ターミナルでもEnterを押す」と挙動が一致する

## 却下した案

- **ターミナルの画面から最後の行を取り出して照合する**: シェルやプロンプトごとに形が違い、Claude Code のような TUI では入力欄が画面の途中にある
- **一致を取れない時は時間切れの後に送る**: 読み返せる入力欄で一致しなかった時に送ると、ADR-014 の「一致した時だけ」が崩れる

## 見直す条件

- ターミナルがアクセシビリティで入力中の行だけを返すようになった時
- 表に無いターミナルで同じ `timedOut` が続く時（表に足す）
