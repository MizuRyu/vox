# ADR-011: HUD の編集モードと、挿入先・検索対象を「トグル ON 時の前面アプリ」で決める

- 状態: **提案**（ユーザー要望 2026-09-02。M2 以降で実装。M1 には入れない）
- 日付: 2026-09-02
- 関連: 設計書 §5（パレット）、§7（訂正）、ADR-004、ADR-005

## 文脈

M1 の実測後にユーザーから 2 つの要望が出た。

1. HUD の文字起こしテキスト領域に**直接文字入力**したい
2. パレットの `@` ファイル検索を、**今 `⌃K` を押した場所（フォーカスしているターミナルの cwd）**を対象にしたい

どちらも可能だが、HUD が「前面アプリのフォーカスを奪わない」（設計書 §4、`.nonactivatingPanel`）という前提に触れる。

## 判断

### 1. HUD 表示中はそのまま打てる（「割り込み」。編集モードは設けない）— 改訂 2026-09-02

初版は「Tab で入る編集モード」だったが、ユーザーの想定は**モードではなく割り込み**だった。
喋っている最中にそのまま打てば、その位置に文字が入る。パレット（`⌃P`）と同じ「割り込み」の一種として一貫させる。

- HUD を表示している間、**HUD が常に key window**。`.nonactivatingPanel` はアプリを activate せずに key window になれるので、
  `show()` 直後に `makeKey()` する。**`NSApp.activate` は呼ばない**（前面アプリは変えない）
- 帰結として **HUD 表示中は前面アプリにタイプできない**。`⌃K` を押した時点で入力先は vox、というモデル。
  T8 の「HUD 表示中も前面アプリに直接タイプできる」は撤回する（「activate しない」は維持）
- 打った文字は caret 位置に入る。音声の final は `committed` の末尾に追記する。caret が末尾なら追従、途中なら動かさない。
  時間順に打った文字と喋った文字が並ぶのが「割り込み」の実体
- **テキスト領域は 1 つ**（改訂 2026-09-02、T11）。`tentative`（淡色）は同じ `NSTextView` の末尾に流れ込み、確定で通常色になって繋がる。
  淡色の末尾は読み取り専用で caret も入れない。M2 で別ラベルにした構成は、実機で「領域が分かれている」と見えたため撤回
- `esc` は破棄（1 回）。`Tab` はテキストビューに素通し
- 録音は止めない
- これは §7「訂正」の候補ポップオーバーを置き換えるのではなく下地にする

### 1-b. テキストは時間順の 3 区画で持つ（T21 の改訂 2026-09-04。同じ場所の 4 回目の変更）

T17〜T20 で「打った文字と淡色のどちらが前か」を 3 回変え、いずれも**打った文字が後から動く**問題が残った。

| 版 | 表示順 | 起きたこと |
|---|---|---|
| T17 | head + 淡色 + 打った文字 | 音声が打った文字の前に入る |
| T18 | 同上（合流を導入） | 淡色が打った文字の前に出て一瞬崩れる |
| T20 | head + 打った文字 + 淡色 | **打った文字が淡色の前に押し戻される** |

**T20 の裁定は誤りだった。** ユーザーは 2 回「打った文字は淡色の後ろに入れてほしい」と言っており、
それを裁定者が「淡色を末尾にすれば時間順になる」という自分の理屈で上書きしていた。

**正しい鍵**: 淡色が出ている時に打ったなら、**その音声は打鍵より前に発話されている**。
だから確定時に音声を打った文字の**前**に入れるのが時間順で、そうすれば打った文字は一度も動かない。

| 区画 | 内容 |
|---|---|
| `head` | 淡色より前に確定したもの（音声の final と、それ以前に打った文字） |
| `tentative` | いま出ている淡色（常に 1 つ） |
| `tail` | 淡色が出た後に打った文字 |

表示順は `head` + `tentative` + `tail`。遷移は 3 つだけ。

1. 淡色の更新 → 淡色の範囲だけ差し替え。`head` と `tail` は不動
2. **確定 → `head += final`、淡色を空に、`tail` は不動**（淡色がその場で通常色に変わるだけ）
3. **淡色が空→非空（新しい発話が始まる）→ 先に `head += tail` して `tail` を空に**（打った文字が、その後の音声より前に確定する）

**不変条件: 打った文字は一度も動かない。** これが T17〜T20 で満たせていなかった要件であり、このモデルの唯一の目的。

### 2. 挿入先と検索対象は「トグル ON 時の前面アプリ」で決める

現状（M1）は挿入先をトグル OFF 時の前面アプリで取っている。編集モードやパレット（M3）で HUD が前面になると、
**自分自身に貼り付ける**ことになるので、これは今のうちに直す。

- トグル ON の瞬間に `frontmostApplication` を覚える（`targetApp`）
- 確定時は `targetApp` を `activate` してから `Cmd+V` を送る。activate の完了を待つ（`NSRunningApplication.activate` は非同期。`didActivateApplicationNotification` か短いポーリングで確認）
- パレットの検索対象も同じ `targetApp` から導く

### 3. ターミナルの cwd はアプリごとのアダプタで取る

| 前面アプリ | 取り方 | 確度 |
|---|---|---|
| Orca | `orca worktree ps --json` の `result.worktrees[]` から `isActive == true` が **1 件だけ**の行を選び、その絶対ローカル `path` を使う。folder workspace（`hostId` / `terminalPlatform` が null）もローカルとして扱う | **確認済み**（2026-09-06。`/` を cwd にして確認） |
| Terminal.app | AppleScript `tell application "Terminal" to tty of selected tab of front window` → その tty の前景プロセス（`ps -t`）→ `proc_pidinfo(PROC_PIDVNODEPATHINFO)` で cwd | 高。既知の手法 |
| iTerm2 | AppleScript で `current session` の `tty`、または iTerm の Python API | 高 |
| VS Code 等のエディタ内ターミナル | ウィンドウタイトルにワークスペース名。パスは直接取れない | 低。ワークスペース設定との突き合わせが要る |
| その他 | ウィンドウタイトル（AX）にパスがあれば解析 | 低 |
| どれも失敗 | Orca のエラー、候補なし・複数の active、空または非絶対パス、remote または archived の候補は選択せず、明示的に設定されたリポジトリへフォールバックする。パレットに「対象を特定できず、設定のリポジトリを表示」と出す | — |

取れた cwd が git リポジトリ内なら、そのリポジトリのルートを検索対象にする（`git rev-parse --show-toplevel`）。
cwd そのものより、リポジトリ単位のほうが「このファイル」と言いたい対象に合う。

## 理由

- 直接編集は、音声入力の「言い直すより打ったほうが速い」場面（固有名詞、記号、1 文字の訂正）を最短で埋める。
  §7 の候補ポップオーバーだけでは「候補に無い」ときに詰む
- 「押した場所で検索」は、看板機能（発話中のパレット）の精度を決める。リポジトリを設定で選ばせるより、
  今いる場所から取るほうが「このファイルの〜」の意図に近い

## 却下した案

| 案 | 却下理由 |
|---|---|
| HUD を activating にする（`NSApp.activate`） | 前面アプリが変わり、確定時に戻す手間と失敗の余地が増える。key window になるだけなら activate は不要 |
| Tab で入る編集モード（初版） | ユーザーの想定と違った。「モード」は覚える負担と `esc` の意味の分岐を生む |
| `tentative` も編集可能にする | 認識結果の更新でカーソル位置と編集内容が壊れる |
| cwd を取らず設定のリポジトリだけにする | 複数リポジトリを行き来する使い方で毎回切り替えが要る |

## 結果として受け入れるもの

- HUD の状態が増える（表示 / 編集 / パレット）。`esc` の意味が状態で変わるので、キーヒントで常に現在の意味を出す
- ターミナルアダプタはアプリごとの保守が要る。まず Orca と Terminal.app の 2 つに絞る

## 見直しの条件

- HUD を常時 key にしたことで、ユーザーが「HUD 表示中も前面アプリに打ちたい」と感じる場面が出たとき → 「打つ前に HUD をクリック」方式（key を取るのを明示操作にする）に切り替える
- Orca の active worktree が 0 件または複数になる、候補がローカルの絶対パスでない、または remote / archived になるケースが見つかったとき → 候補を拒否し、明示的に設定されたリポジトリへフォールバックする
