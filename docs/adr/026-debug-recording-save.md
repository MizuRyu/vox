# ADR-026: 設定でオンにした回だけ、認識に渡した音声を wav で残す

- 状態: **提案**（2026-10-18）
- 関連: [ADR-017](017-image-paste-as-file-path.md)（私的ファイルの保存と回収）、[ADR-018](018-no-engine-switch.md)（自作コーパスでの比較）、[ADR-008](008-reference-text-convention.md)（正解テキスト）

## 文脈

利用者の訴えが 2 つある。録音キーを押してすぐ話すと最初の文字が欠けること、誤字・脱字が多いこと。
どちらも今の記録では原因を切り分けられない。

- 頭切れ: マイクは `SpeechAnalyzer.start` の後に開く。計測 641 回でトグル ON から analyzer 起動までは中央値 55ms・最大 534ms、発話開始は中央値 675ms で 500ms 未満が 19%。
  「マイクが開く前の音が録れていない」のか「録れているがモデルが頭を落とす」のかは、音声が無いと決められない。直し方が違う（開く順序か、先頭の扱いか）
- 誤字: [ADR-018](018-no-engine-switch.md) の見直しの条件は「自作コーパスで Apple の日本語 CER を測ること」だが、コーパスが無く止まっている。履歴には本文しか残らない

## 判断

1. **設定「デバッグ: 録音を保存する」を足す。既定はオフ。** オンの間、1 回の録音を 1 つの wav と、同じ名前の JSON に残す
2. **保存するのは analyzer に実際に渡した音声（変換後）。** 同じ入力で認識を再現でき、他のモデルにもそのまま渡せる。形式は実行時に決まる（Int16 のことがある）ので固定せず、JSON にレート・チャンネル数・フレーム数を書く
3. **JSON には、その回の履歴の行と計測の行をそのまま入れる。** 加えて、最初の音声バッファを受け取った時刻（`capture_start_ms`）を書く。頭切れの切り分けに使う
4. **確定まで進んだ回だけ残す。** 確定の失敗と入力デバイスの変化も、履歴を書く回なので残す。破棄（Esc、話さずに終わった回）、開始の失敗、終了は消す
5. **書き込みは main actor の外の直列キューで行う。** 認識と貼り付けを待たせない。保存に失敗しても録音は続け、診断ログに 1 行だけ残す
6. 保存先は `~/Library/Application Support/vox/recordings/<yyyyMMdd>/<HHmmss>-<nn>.wav|json`（フォルダ 0700、ファイル 0600）。**起動時に 7 日・合計 500MiB で回収し、wav と JSON は組で消す**（画像とは別の枠）
7. 1 回の録音の上限は 30 分。超えた分は書かず、JSON に `truncated: true` を残す
8. 設定画面に保存先を開くボタンを置く

## 却下した案

- **変換前（機器の形式）で残す**: 機器ごとにレートとチャンネルが違い、比較のたびに変換が要る。モデルに渡した音と一致しないので頭切れの切り分けにも使えない
- **常にマイクを開いて直前の音を残す**: 頭切れは直るかもしれないが、メニューバーのマイク表示が出続ける。録音の外の音を持つことになる
- **計測に `capture_start_ms` を足す**: 全回に要る値ではない。保存した回の JSON にあれば切り分けには足りる（[ADR-018](018-no-engine-switch.md) の「欄を先に足さない」と同じ考え）
- **破棄した回も残す**: 正解データ作りにも頭切れの切り分けにも要らず、言い直す前の声を残すだけになる

## 見直しの条件

- 頭切れの原因が決まり、修正の効果を確かめ終えたとき（設定を残すかを決め直す）
- 自作コーパスを別の方法で用意できるようになったとき
- 30 分・500MiB の上限で、正解データ作りに要る回が消えたとき
