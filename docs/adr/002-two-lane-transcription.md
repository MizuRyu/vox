# ADR-002: 速報と確定の二段構成。目的は「確定直前の書き換え」を消すこと

- 状態: **承認**
- 日付: 2026-09-01（目的の再定義は 2026-09-01 の調査で）
- 関連: 設計書 §2

## 文脈

リアルタイム表示（喋った瞬間に文字が出る）と、確定テキストの精度を両立させたい。
ストリーミング ASR は右文脈を持てず、バッチ ASR は発話が終わるまで出力できない。

## 判断

**2 レーンを並走させる。** 速報レーンは淡色で「書き換わる前提」の未確定テキストを出し、
確定レーンは発話区切り（VAD）ごとに一度だけ上書きし、以後動かさない。

## 理由（初版から変えた）

初版は「リアルタイム性と精度は単一モデルでは両立しない」を根拠にした。調査でこの根拠は弱いと分かった。

- 速報 CER 13.79% vs 確定 6.88% の比較は**別データセット**（FLEURS vs JSUT）の値だった。同一データセットでは 13.79% vs 10.29% で差は 3.5pt
- 上流 Nemotron の日本語 CER はチャンク 1.12s → 80ms で 11.48% → 13.87% と **2.4pt しか動かない**。「遅延を削ると日本語が崩れる」は支持されなかった

そこで目的を**精度ではなく書き換えの排除**に再定義した。

- Partial Rewriting の研究 (arXiv:2312.09463): 二段構成の flicker は未確定→未確定では増える（dictation +75%）が、**最後の未確定→確定では 50% 減る**、総合 13% 減
- 日本語は同音異字のため**表示済みの漢字が別の漢字に差し替わる**。英語の語末追記より視覚的にはるかに目立つ。確定の瞬間に文がガラッと変わる体験は、遅延そのものより不快

確定テキストは挿入されて手元に残るものなので最良のモデルを使い、速報は「今喋れている」というフィードバックであって正確さの担保ではない。

## 却下した案

| 案 | 却下理由 |
|---|---|
| ストリーミング単体 | 未確定テキストが表示されたまま何度も書き換わり続ける。確定の契機がない |
| バッチ単体 | 喋っている間に何も出ない。決定 2（速さが売り）に反する |
| 速報をひらがなで出す | 同音異字の書き換えを目立たせない狙いで理屈上あり得るが、実装例が見つからず未検証。未決事項 5 として残す |

## テキスト契約

Handy 方式 `{ committed, tentative, revision }` を採用。`committed` は追記専用で一度出したら動かさない → UI 側で flicker が原理的に起きない。
日本語は分かち書きがないため VoiceInk の `WordAgreementEngine`（単語 3 回一致で確定）は移植できない。文字 / subword 単位で確定判定する。

## 見直しの条件

- M0 で速報レーンのエンジンが決まらない（どれも決定 3 を満たさない）とき → 速報の「見せ方」を変える案（文字でなく「聞いている」表示）を検討する。二段構成そのものは維持
