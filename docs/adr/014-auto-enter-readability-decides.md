# ADR-014 自動 Enter は読み返せるかで自動判定し、読めないときの送信だけを設定にする

- 状態: 承認
- 日付: 2026-09-08
- 関連: ADR-009（promise pasteboard）、[06 権限とリスク](../specs/06-permissions-and-risks.md)

## 文脈

自動 Enter には 2 つの方式があり、利用者が設定画面で選んでいた。

- `verified`: 貼り付け後に入力欄を読み返し、本文・カーソル・入力先が一致したときだけ Enter を送る。
- `after_paste`: 読み返さず、貼り付けから 0.5 秒待って同じアプリ・ウィンドウなら Enter を送る（ターミナル向け）。

2 つの実差は「入力欄を読み返せなかったときに送るか諦めるか」だけだった。読み返せるかは貼り付けのたびに AX で分かるので、
利用者に方式を選ばせても、判断材料は「自分の使うアプリが読める側かどうか」でしかない。
実際 `verified` を選んだ利用者はターミナルで Enter が届かず、`after_paste` を選んだ利用者は読める入力欄でも確認を捨てていた。

## 決定

方式の選択を廃止し、動作を常に次の 1 つにする。

1. 読み返せる入力欄では、読み返して一致を確認したときだけ Enter を送る。
2. 読み返せない入力欄では、設定「入力欄を確認できないアプリ（ターミナルなど）でも送る」（`auto_enter_unverified`、既定オフ）に従う。
   オンなら 0.5 秒待って同じアプリ・ウィンドウであれば送り、オフなら送らない。

判定・待ち時間・拒否理由の優先順（修飾キー → 入力先変更 → クリップボード競合 → 取り消し → 期限）は方式ごとの現行動作をそのまま引き継ぐ。
`auto_enter_mode` は読むだけ残し、`after_paste` を選んでいた設定は `auto_enter_unverified = true` として引き継ぐ。書き戻さないので `schema_version` は 1 のまま。

## 却下した案

- **方式を利用者が選ぶ（現状維持）**: 選択の材料が「読めるかどうか」しかなく、それはアプリごとに毎回変わる。
  1 つの設定でターミナルとエディタを両立できない。
- **常に読めないときも送る**: 確認できないまま Enter を送るのは、送信・コマンド実行になりうる操作としては既定にできない。
- **設定を全廃し、読めないときは常に諦める**: ターミナル（読み返せない AX）で自動 Enter が一切使えなくなり、既存利用者の用途を落とす。

## 見直しの条件

- ターミナル系アプリが AX で入力欄の内容を返すようになり、「読めない」経路が実質使われなくなったとき。設定ごと落とす。
- 読めない側で誤送信の報告が出たとき。0.5 秒の猶予とウィンドウ確認では足りないので、送信条件を足すのではなく設定を廃止する側に倒す。
