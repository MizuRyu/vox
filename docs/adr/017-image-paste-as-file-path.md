# ADR-017 貼り付けた画像は一時ファイルに書き、本文にはパスを入れる

- 状態: 承認（2026-09-24。ATT-01 を実機で確認: 画像だけを貼るとパスが本文に入り、貼り付け先にも渡った）
- 日付: 2026-09-23
- 関連: [ADR-009 テキスト挿入は promise pasteboard 方式](009-text-insertion-promise-pasteboard.md)、[ADR-014 自動 Enter は読み返せるかで決める](014-auto-enter-readability-decides.md)、[08 画像の添付](../specs/08-image-attachments.md)、[使い方](../usage.md#録音と貼り付け)

## 文脈

HUD に画像を貼りたいという要求に対し、実現方法は 3 つある。(a) 貼り付け先へ画像そのものをペーストボードで渡す、(b) 一時ファイルに書いて本文にパスを入れる、(c) 貼り付け先が画像を受けるかで切り替える。

現状を確かめると、(b) の経路は大半が既にある。HUD の本文ビューは T20 で `⌘V` を上書きし、ペーストボードにファイル URL があればそのパスを本文に入れる（`TranscriptFilePaste` → `FilePathFormat`）。Finder でコピーした画像ファイルは既に貼れる。欠けているのは「クリップボードに画像データしか無い」場合（スクリーンショット、ブラウザからのコピー）で、このとき素の `NSTextView` は何も入れずに終わる。

(a) には本体側の制約が 2 つある。1 つは、1 つのペーストボード item に `.string` と画像型を併記すると貼り付け先がどちらか一方を採るため、本文と画像の両方を渡すには `⌘V` を 2 回送る必要があること。ADR-009 の手順（退避 → promise → 1 回の `⌘V` → 受領証 → 猶予つき復元）は 1 回の貼り付けを前提に組んであり、2 回に分けると途中で前面アプリが変わった場合の状態が定義できない。もう 1 つは ADR-014 の自動 Enter が「挿入テキストを当てた期待値と入力欄の読み返しの一致」だけを根拠にしていることで、画像を貼った回は一致が成立せず、必ず「確認できないので押さない」に落ちる。

さらに (a) と (c) の中核である「この貼り付け先は画像を受けるか」の表は、Vox 本体を起動して実アプリへ貼らないと埋まらない。AGENTS.md はエージェントによる本体起動を禁じているため、この表は検証されないまま残る。ADR-009 の `asyncConsumerBundleIdentifiers` も同種の表だが、あちらは外れても復元が遅いだけで、画像の表は外れると本文が失われる。

Vox の貼り付け先はターミナル、エディタ、コーディングエージェントが主で、これらに対してはパス文字列の方が画像そのものより扱いやすい（受け手が必要な回数だけ読める、本文に残る、履歴に残せる）。

## 決定

1. **クリップボードの画像データは `~/Library/Application Support/vox/attachments/` 配下の 1 ファイルに書き、本文にはそのパスを入れる。** 表記と挿入位置は既存のファイルペーストと同じ（`FilePathFormat` + `PaletteInsertion`）。画像そのものを貼り付け先へ渡す経路は作らない。
2. **ペーストボードにファイル URL があるときはコピーしない。** 既にあるファイルのパスをそのまま入れる（今日の挙動を変えない）。テキストが同時にあるときは通常のテキストペーストに落とす（本文を壊さない側を選ぶ、という T20 の規則を継承する）。
3. **バイト列は再エンコードせずそのまま書く。** 対応形式は png / jpeg / heic / gif / tiff で、選ぶ優先順もこの順。拡張子は形式から決め、`ImageIO` に依存しない。1 枚の上限は 32MiB。PDF・ベクタ・動画は対象外（画像ではない）。
4. **書き込みが終わってからパスを本文に入れる。** これにより「本文にパスがある ⇒ ファイルが存在する」が不変になる。書き込みは main actor の外で行い、確定（トグル OFF）は `palette.awaitPendingFinalize()` と同じ形で未完の書き込みを待つ。`AutoEnterGate` には条件を足さない。gate は入力欄を読み返せるかだけを見る型であり、貼り付け前の準備状態を渡さない。
5. **消去は期限と合計サイズによる回収だけにする**（既定 7 日 / 合計 500MiB、起動時に 1 回）。確定から N 分で消す方式は採らない。渡したのはパスであり、受け手がそれを開くのは本文を受け取った後だからである。
6. **画像は履歴・計測・診断ログに残さない。** 履歴の `inserted_text` に載るのは本文（パス文字列を含む）までで、これは既存のパレット挿入と同じ。`--log-text` でも画像バイトは出ない。診断ログのパスは既存の `voxLoggable(path:)` でマスクし、形式とバイト数だけを残す。ファイル名は日時と連番だけで作り、発話内容・貼り付け先アプリ名・画像の内容を含めない。計測 JSONL には項目を足さない（軸 A の母数に添付は影響しない）。
7. **サムネイル列は作らない。** 添付の存在・順序・削除の真実は本文 1 つに保つ（確認は本文のパス、削除はパスを消す、順序は本文の並び）。失敗の 1 行は HUD のキーヒントの行に 2.5 秒だけ出す。中段の `notice` は本文の表示を置き換えてしまうため、録音中の失敗には使わない。
8. **振り分け・名前・回収の判定は VoxCore（`Attachments/`）の純粋関数に置く。** Vox 側にはペーストボードの読み取り、ファイル書き込み、待ち合わせだけを残す。ペーストボードの型名は VoxCore が文字列で持ち、AppKit の値との一致は `VoxAppTests` が突き合わせる（VoxCore は AppKit を持てない）。

## 却下した案

| 案 | 却下理由 |
|---|---|
| (a) 貼り付け先へ画像そのものを渡す（`NSPasteboard` に text + image を併記） | 1 item では貼り付け先がどちらか一方の型を採るため、本文と画像の両方を渡すには `⌘V` が 2 回になり、ADR-009 の 1 回性が崩れる。ADR-014 の自動 Enter は画像を貼った回に必ず「確認できない」へ落ちる |
| (c) 貼り付け先の bundle id と型の表で (a)/(b) を切り替える | (a) の欠点を引き継ぐうえ、表が本体起動なしでは検証できない。外れたときに失われるのが本文なので、`asyncConsumerBundleIdentifiers` 型の未検証リストとして許容できる範囲を超える。同じ操作の結果がアプリ依存で変わる説明も利用者にできない |
| 画像を `ImageIO` で png に正規化する | 品質・EXIF・向きの判断と依存が増える。バイト列をそのまま書けば、形式の追加は拡張子表の 1 行で済む |
| ファイル URL でも `attachments/` へコピーする | 同じ画像の複製が増える。元の場所のパスを渡す方が受け手にとっても正しい |
| 確定から N 分（または次の録音開始）で消す | 渡したのはパスであり、コーディングエージェントやエディタが開くのは本文を受け取った後。プライバシーのための消去が「画像が読めない」不具合として現れる |
| HUD にサムネイル列を先に作る | 添付の存在と順序の真実が本文とサムネ列の 2 つになり、`TranscriptBuffer` の外側に新しい整合規則が必要になる。段階 1 では本文だけで確認・削除・順序が足りる |
| 失敗を中段の `notice` に出す | `notice` は本文の表示と入れ替わる。録音中に出すと打った文字と認識結果が見えなくなる |
| 画像を base64 で本文に埋める | 本文の文字数が計測・履歴・貼り付けの全経路を汚す。貼り付け先でも読めない |

## 見直しの条件

- **画像を表示して読ませる相手（チャット、メール、Slack、ブラウザのフォーム）が主用途になったとき。** そのとき本題は「本文と画像の 2 回貼りをどう安全にするか」なので、本 ADR の追記ではなく別の ADR を立てる。確認は [ATT の TC](../MANUAL-VERIFICATION.md#att--画像の添付) と、利用者による実アプリでの貼り付け。
- **「本文にパスがあるのにファイルが無い」が実機で起きたとき。** 決定 4 の不変条件か決定 5 の回収が破れている。確認は診断ログの `attachment_saved` / `attachment_purged` 行と履歴の `inserted_text`、回帰検証は `nix develop -c just verify`。
- **対応形式で保存できない画像（ベクタ、PDF、動画）を貼る要求が出たとき。** 決定 3 の形式表の範囲を見直す。再エンコードを入れるかは別に判断する。
- **7 日 / 500MiB で容量か私的データの残り方が問題になったとき。** 決定 5 の値だけを見直す（方式は変えない）。
