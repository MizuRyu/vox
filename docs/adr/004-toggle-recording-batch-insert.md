# ADR-004: 録音はトグルのみ、認識結果は HUD 内に表示して終了時に一括挿入

- 状態: **承認**
- 日付: 2026-09-01
- 関連: 設計書 §0 決定 4・5、§4 キー体系

## 文脈

看板機能は「発話の途中でコマンドパレットを開いてファイルパスを差し込む」。
録音の起動モデルと、認識結果をどこに出すかが、この機能の成立を左右する。

## 判断 1: 録音はトグルのみ（押して開始、押して終了）

push-to-talk（押している間だけ録音）を採らない。

**理由**: キーを押し続けながらパレットに文字を打てない。push-to-talk を選ぶと看板機能が死ぬ。
参照した既存ツールは「Control を押したまま J を 2 回でロック」という回避策を持っていたが、
それは看板機能を「ロックを覚えているユーザー」限定にする。

副次的な利点: keyup を取る必要がないので、macOS 26 のホットキー問題（VoiceInk #735）の影響が小さい。

**代償**: 切るのを忘れるとマイクが生きたままになる。

## 判断 2: HUD 内に表示 → 終了時に一括挿入

前面アプリへの逐次挿入を採らない。

**理由**: 二段構成（ADR-002）の確定レーンは速報テキストを**上書き**する。逐次挿入していると、
他アプリへ送った文字を backspace 連打で消して打ち直すことになり、相手の undo 履歴も破壊する。
訂正機能（§7）も、挿入済みのテキストには効かない。
HUD 内で完結させれば、上書きも訂正もパレットのパス挿入もすべて HUD 内で済み、
前面アプリには完成したテキストが 1 回だけ入る。調査した全ツールがこの形。

## 却下した案

| 案 | 却下理由 |
|---|---|
| push-to-talk + ロック | 看板機能がジェスチャーの裏に隠れる。keyup 検知が必要 |
| トグルと push-to-talk を設定で選べる | 最終形としては正しいが、v1 でパレットの挙動がモードで分岐しテストの組み合わせが倍になる |
| 前面アプリに逐次挿入 | 上記。二段構成と訂正が成立しない |
| 確定セグメントごとに逐次挿入 | 上書きは起きないが、送った後の訂正ができず訂正機能と排他になる |

## 導かれるキー体系

トグルが「開始」と「確定して挿入」を兼ねるので `Enter` で録音を終える必要がなくなった。
`⌘⇧Space` 開始/確定して挿入、`esc` 破棄、`⌃K` パレット、`⌃Z` 訂正。`Enter` はパレット内でのみ使う。

## 見直しの条件

- v1 が安定した後、短い口述向けに push-to-talk を**追加**することは妨げない（置き換えではなく追加）
