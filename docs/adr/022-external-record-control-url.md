# ADR-022: ほかのアプリから録音を開始・確定する入口を URL スキームで開ける（既定はオフ）

- 状態: **提案**（2026-09-24）
- 関連: [ADR-004](004-toggle-recording-batch-insert.md)（録音はトグル）、[ADR-009](009-text-insertion-promise-pasteboard.md)（貼り付け）、[ADR-014](014-auto-enter-readability-decides.md)（自動 Enter）、[ADR-020](020-pause-triggered-segment-commit.md)（無音の検出）、[仕様 03](../specs/03-architecture.md)

## 文脈

利用者は、声だけで Claude Code と対話する別の道具（parley、別リポジトリ）を作る。流れは「Hey Siri で録音を始める → 話す → 黙ったら確定して貼り付け + Enter → 応答を読み上げる」。
vox は録音キー（CGEventTap）とメニューバーからしか録音を始められず、確定も録音キーだけである。
キーボードに触らずに使うには、ほかのアプリ（Siri から呼ばれるショートカット）が録音を始め、声が止んだら vox 自身が確定する必要がある。

## 判断

**`vox://` の URL スキームで録音を操作できるようにする。受け付けるのは設定「ほかのアプリからの操作を許可」がオンの時だけで、既定はオフ。**

| URL | 動作 |
|---|---|
| `vox://record/start` | 待機中なら録音を始める。それ以外の状態では何もしない |
| `vox://record/finish` | 録音中なら確定して貼り付ける。それ以外の状態では何もしない |
| `vox://record/toggle` | 録音キーを 1 回押したのと同じ（待機中なら開始、録音中なら確定） |

`start` と `toggle` の開始側は、クエリで 2 つを指定できる。利用者・パスワード・ポート・フラグメントを含む URL は拒む。

- `target=<bundle identifier>`: 貼り先のアプリ。起動していればそのアプリを貼り先に固定する。指定が無ければ、URL を受け取った時点の前面アプリ（メニューバーから始める時と同じ判定。vox 自身は除く）
- `finish_after_silence_ms=<ミリ秒>`: 発話のあと、この時間だけ無音が続いたら確定する。範囲は 800〜10,000。範囲外や数字でない値は URL ごと拒否する。無音の判定は ADR-020 と同じ `AudioLevelTracker`（ノイズ床 × 4）で、条件は次のすべて
  1. 録音開始より後に発話があった
  2. 最後の発話から指定の時間以上、発話レベルを超えていない
  3. 本文（確定・未確定・手入力のどれか）が空でない
  4. パレットが開いていない
  5. 無音での区切り（ADR-020）の締めが走っていない（同じ analyzer に finalize を重ねない）。締めが 1,000 ms を過ぎても返らない時は待つのをやめ、録音キーで確定した時と同じ経路（締めの待ちと本文の救済）に任せる

確定の後の貼り付け・自動 Enter・安全確認は、録音キーで確定した時と同じ経路を通る。

- 判定は VoxCore の純粋な型に置く: URL の解釈（`ExternalCommand`）、設定と録音の状態による受け付けの判定（`ExternalCommand.decision`。判定の直前に設定を読み直す）と無音での確定（`SilenceFinishPolicy`）
- 外からの開始は、判定の直前に読んだ設定でそのまま録音を始める（開始時にもう一度読み直さない）
- 設定は `settings.json` の `external_control_enabled`（bool、既定 `false`）
- 診断ログは `external_command kind=start|finish|toggle accepted=true|false reason=…`。`target` の bundle identifier は出してよい（既存の `target_app` と同じ扱い）
- URL で本文を渡す口・本文を受け取る口は作らない

## 理由

- **URL スキームを選ぶ**: macOS のショートカットは「URL を開く」だけで呼べ、Siri の語句をショートカット名で決められる。CLI（`vox --toggle`）は起動中のインスタンスへ伝える経路（分散通知など）を別に作る必要があり、ショートカットからはシェルスクリプトの実行が要る
- **既定をオフにする**: URL スキームは、Web ページのリンクや任意のアプリからも開ける。オンのままだと、利用者の知らないところで録音が始まりうる。ブラウザは独自スキームを開く前に確認を出すが、それに頼らない。録音中は HUD が必ず出るので、オンにした後の不意の開始には気づける
- **無音での確定を URL の指定に限る**: 録音キーで始めた時は、利用者が考えながら間を置くことがある。黙っただけで確定すると書きかけが送られる。声だけで使う時だけ、呼び出し側が明示する
- **`target` を用意する**: Siri やショートカットから呼ぶと、前面アプリが呼び出した側に変わる可能性がある（未検証）。貼り先を固定できれば、この不確かさを呼び出し側で消せる

## 影響

- 設定画面に 1 項目、`settings.json` に 1 フィールド、Info.plist に URL の宣言が増える
- 録音キーでの挙動は変わらない（無音での確定は URL で指定した録音だけ）
- `finish_after_silence_ms` の録音は、利用者が黙って考える間に確定してしまう。短すぎる値は範囲で防ぐ

## 却下した案

- **CLI の引数で起動中のインスタンスを操作する**: 伝える経路を別に作る必要がある。ショートカットからはシェルスクリプトが要る
- **AppleScript の辞書（sdef）を公開する**: 自動化の許可ダイアログがもう 1 つ増え、定義ファイルの保守が要る
- **既定でオンにする**: 上の「理由」のとおり、不意の録音開始を防げない
- **無音での確定を設定項目にして、録音キーでも効かせる**: 書きかけが送られる。ADR-020 の区切り（確定色にするだけ）とは影響の大きさが違う
- **URL で本文を渡して貼り付けさせる**: vox が任意の本文を任意のアプリに貼る道具になる。音声入力の範囲を超える

## 見直す条件

- Siri やショートカットから呼んだ時に、前面アプリが呼び出し側に変わることが実機で分かった時（`target` を必須にするか、既定の判定を変える）
- 無音での確定が早すぎる・遅すぎるという実測が出た時（範囲の見直し。既定値は呼び出し側が持つ）
- URL 以外から同じ操作が要る時（例: CLI からの常時利用）
