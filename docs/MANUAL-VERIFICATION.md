# 手動確認

エージェントは Vox 本体を起動しないため、以下は利用者が実機で確認する。TC-ID は永続識別子（変更・再利用しない）。
自動検査で代替できた項目は「自動化済み: <テスト名>」と注記して手動対象から外す。

## 実行のしかた

`just install` した `/Applications/Vox.app` で確認する。確認日と VERSION を下の表に記録する。

| 確認日 | VERSION | 確認者 |

| | | |

## SETUP — 初回起動と権限

### SETUP-01 初回起動でセットアップ画面が開く

| 項目 | 内容 |
|---|---|
| **前提** | Vox を初めてインストールした状態（アクセシビリティ・入力監視・マイクいずれも未許可） |
| **手順** | `/Applications/Vox.app` を開く |
| **期待結果** | セットアップ画面が開き、マイク・アクセシビリティ・入力監視の3項目が番号付きで表示される |

### SETUP-02 3つの権限を順に許可すると緑チェックが付く

| 項目 | 内容 |
|---|---|
| **前提** | セットアップ画面が開いている |
| **手順** | マイク → アクセシビリティ → 入力監視の順にシステム設定で許可し、Vox のセットアップ画面に戻る |
| **期待結果** | 許可した項目に緑のチェックが付く。3項目とも許可するとメニューバーとDockの通常動作に進める |

### SETUP-03 「状態を再確認」で権限反映を確認する

| 項目 | 内容 |
|---|---|
| **前提** | システム設定で権限を許可した直後、セットアップ画面のチェックが更新されていない |
| **手順** | 「状態を再確認」を押す |
| **期待結果** | 許可済みの項目に緑のチェックが反映される。反映されない場合は macOS が再起動を求めていないか確認する |

### SETUP-04 メニューが見つからないときに再度アプリを開くとセットアップ画面が出る

| 項目 | 内容 |
|---|---|
| **前提** | Vox が起動しているがメニューバー項目が見当たらない |
| **手順** | `/Applications/Vox.app` をもう一度開く |
| **期待結果** | セットアップ画面が開く |

## REC — 録音開始・確定・破棄

### REC-01 録音開始でHUDが表示される

| 項目 | 内容 |
|---|---|
| **前提** | 権限3項目を許可済み。任意の入力欄にカーソルがある |
| **手順** | 録音キー（既定 `⌘⇧Space`）を押す |
| **期待結果** | HUD が表示され、話した内容が本文に反映される |

### REC-02 録音キーで確定し貼り付けられる

| 項目 | 内容 |
|---|---|
| **前提** | REC-01 の状態で録音中 |
| **手順** | 録音キーをもう一度押す |
| **期待結果** | HUD が閉じ、確定した本文が最初にカーソルを置いていたアプリへ貼り付けられる |

### REC-03 Escで録音中の本文を破棄する

| 項目 | 内容 |
|---|---|
| **前提** | 録音中で HUD に本文がある |
| **手順** | `Esc` を押す |
| **期待結果** | HUD が閉じ、本文はどこにも貼り付けられない |

### REC-04 録音中の手入力が音声と混在する

| 項目 | 内容 |
|---|---|
| **前提** | 録音中で HUD にフォーカスがある |
| **手順** | 音声で話しながら、キーボードで文字を追記・編集する |
| **期待結果** | 手入力した文字が音声認識の結果と衝突せず、両方が本文に反映される |

### REC-05 フィラー除去

| 項目 | 内容 |
|---|---|
| **前提** | 「えっと」「あの」等のフィラーを含む発話をする |
| **手順** | 録音して確定する |
| **期待結果** | 文頭・読点間の単独フィラーが除去され、単語の一部や「なんか」等の非対象語は残る |
| **自動化済み** | `swift test --filter "FillerTests"`（`Solo filler at sentence start is removed` ほか、`Nanka is kept` 等の残す側を含む一連） |

### REC-06 話している最中の確定でも本文が残る

| 項目 | 内容 |
|---|---|
| **前提** | 録音中で、HUD に淡色（認識途中）の本文が出ている |
| **手順** | 言い終わる前に録音キーを押して確定する |
| **期待結果** | 締めが失敗した回も、HUD に見えていた本文がそのまま貼り付けられる（本文が消えない） |

### REC-07 パレットを開き直した直後の確定でも締めが二重に走らない

| 項目 | 内容 |
|---|---|
| **前提** | 録音中で、HUD に淡色（認識途中）の本文が出ている |
| **手順** | `⌃P` → `Esc` → 1 秒以内にもう一度 `⌃P` → 続けて録音キーで確定する |
| **期待結果** | 確定が完了し、本文が貼り付けられる。診断ログに `segment_finalize_error` が出ない |

### REC-08 録音中に入力デバイスが変わっても本文が残る

| 項目 | 内容 |
|---|---|
| **前提** | AirPods などのヘッドセットを既定入力にして録音し、HUD に本文が出ている |
| **手順** | 録音中に AirPods を外す（または既定入力を切り替える） |
| **期待結果** | 録音が終わり、ここまでの本文が貼り付けられる（HUD が「録音中」のまま残らない）。診断ログに `audio_configuration_changed` が 1 行出る。貼り付けを確認できなかった回は HUD に「入力デバイスが変わったため、ここまでの本文を貼り付けます」が残る |

## PASTE — 元アプリへの貼り付け

### PASTE-01 元のアプリへ貼り付けられる

| 項目 | 内容 |
|---|---|
| **前提** | テキストエディタ等にカーソルを置いて録音を開始した |
| **手順** | 録音キーで確定する |
| **期待結果** | 録音開始時にカーソルがあったアプリ・入力欄に本文が貼り付けられる |

### PASTE-02 入力先が変わったときは貼り付けを省略する

| 項目 | 内容 |
|---|---|
| **前提** | 録音を開始した後、確定前に前面アプリまたはフォーカス中の入力欄を切り替える |
| **手順** | 別のアプリ・別の入力欄に切り替えてから録音キーで確定する |
| **期待結果** | 貼り付けが行われない。履歴に `input_target_changed_process` または `input_target_changed_focus` が記録される |

### PASTE-03 履歴に `error` が記録される

| 項目 | 内容 |
|---|---|
| **前提** | PASTE-02 のように貼り付けが成立しない状況を作る |
| **手順** | `~/Library/Application Support/vox/history.jsonl` の最新行を確認する |
| **期待結果** | 空欄ではなく [development.md のデータの場所](development.md#データの場所) にある `error` 表のいずれかの値が記録されている |

### PASTE-04 入力欄を取得できないアプリでは同一プロセスまで確認する

| 項目 | 内容 |
|---|---|
| **前提** | AX でフォーカス要素を取得できないアプリ（ターミナル等）にカーソルを置いて録音する |
| **手順** | そのまま確定する |
| **期待結果** | 前面アプリのプロセスが録音開始時と同じであれば貼り付けられる。別プロセスに切り替えていれば省略される |

### PASTE-05 貼り付けを省略した回も本文がクリップボードに残る

| 項目 | 内容 |
|---|---|
| **前提** | テキストエディタ等にカーソルを置いて録音を開始した |
| **手順** | 録音キーの修飾キー（`⌘⇧` 等）を押したまま確定し、HUD の通知を読んでから別の入力欄で `⌘V` を押す |
| **期待結果** | 「貼り付けませんでした。本文はクリップボードにあります」と表示され、`⌘V` で確定本文が貼り付けられる |

## ENTER — 自動 Enter

### ENTER-01 読み返せる入力欄で Enter が送られる

| 項目 | 内容 |
|---|---|
| **前提** | 設定で「貼り付け後にEnterを押す」ON、「ターミナルでもEnterを押す」OFF |
| **手順** | テキストエディタなど、入力欄を読み返せるアプリで録音して確定する |
| **期待結果** | 貼り付け後、本文・カーソル・入力先が一致した場合だけ Enter が送られる |

### ENTER-02 読み返せない入力欄では設定が送信を決める

| 項目 | 内容 |
|---|---|
| **前提** | 設定で「貼り付け後にEnterを押す」ON |
| **手順** | ターミナルアプリで、「ターミナルでもEnterを押す」を OFF・ON の順で録音して確定する |
| **期待結果** | OFF では Enter を送らず「貼り付けた内容を確認できないアプリのため、Enterは押していません」と表示する。ON では貼り付けから 0.5 秒以上待ってから、同じアプリ・ウィンドウであれば Enter が送られる |

### ENTER-03 修飾キーが押されたままだとEnterを省略する

| 項目 | 内容 |
|---|---|
| **前提** | 自動 Enter が ON |
| **手順** | 録音キーの修飾キー（`⌘⇧` 等）を離さずに保持したまま確定する |
| **期待結果** | 修飾キーが離されるまで待ち、期限内に離されなければ Enter を省略する |

### ENTER-04 確定待ち中にEscを押すとEnterだけ取り消せる

| 項目 | 内容 |
|---|---|
| **前提** | 自動 Enter が ON。確定後、Enter 送出までの待機中 |
| **手順** | 待機中に `Esc` を押す |
| **期待結果** | 本文の貼り付けは維持されたまま、Enter の送出だけが取り消される |
