# 手動確認

エージェントは Vox 本体を起動しないため、以下は利用者が実機で確認する。TC-ID は永続識別子（変更・再利用しない）。
自動検査で代替できた項目は「自動化済み: <テスト名>」と注記して手動対象から外す。

## 実行のしかた

`just install` した `/Applications/Vox.app` で確認する。確認日と VERSION を下の表に記録する。

| 確認日 | VERSION | 確認者 |

### REC-09 自動選択で音楽再生と録音を併用する

| 項目 | 内容 |
|---|---|
| **前提** | 内蔵マイクがある Mac。macOS の既定入力・出力を Bluetooth ヘッドセットにし、Apple Music を再生。「使用するマイク」は自動、通話向け処理はオフ |
| **手順** | 利用者が録音開始・確定・破棄をそれぞれ試し、音楽の継続と認識を確認。再生停止時、既定入力が USB の場合、可能なら内蔵マイクがない Mac でも確認する |
| **期待結果** | Bluetooth 出力稼働中は内蔵入力を選び、`audio_input` が `selection=automatic` と `transport=builtin` を含む。録音の開始後に `audio_input_verified device_id= route=input_only` が出て、`audio_configuration_changed` が出ない。その他の条件では既定入力。macOS 全体の既定設定は変わらない。音楽の途切れ・音量低下・認識の欠落がないかは機器ごとに記録する |
| **検証状況** | 選択条件は `MicrophoneInputTests`、IO の読戻しは `InputConfigurationTests` で自動化済み。2026-09-23 に AirPods で Music を再生したまま、内蔵マイクでの録音・確定と音楽の継続を利用者が確認。破棄、既定入力が USB の場合、内蔵マイクがない Mac は未確認 |

### REC-10 指定マイクの切断と再接続

| 項目 | 内容 |
|---|---|
| **前提** | 接続した USB マイクなどを Vox で指定し保存している |
| **手順** | マイクを切断して録音開始。再接続後に同じ設定のまま録音する |
| **期待結果** | 未接続時は開始エラーになり、既定マイクへ戻らない。設定の「更新」でも未接続の指定は保持する。再接続後は同じ UID の機器を使い、数値の AudioDeviceID が変わっても録音できる |
| **検証状況** | 解決・保存・未接続表示の組立ては `MicrophoneInputTests` / `MicrophoneTests` / `SettingsViewTests` で自動化済み。実機の再接続は未確認 |

### REC-11 録音中の設定変更は次回に反映する

| 項目 | 内容 |
|---|---|
| **前提** | 異なる入力マイクが2つ使える状態。「使用するマイク」は一方の明示指定 |
| **手順** | 録音中にもう一方を選んで保存。録音を確定してから再度録音する。「macOSの既定」でも繰り返す |
| **期待結果** | 録音中に入力を切り替えず、次回の準備時に保存した選択を使う。macOSの既定モードは、自動選択の Bluetooth 条件に該当しても既定入力を使う |
| **検証状況** | 設定の固定は `recordingSessionSnapshot`、選択の優先順位は `MicrophoneInputTests` で自動化済み。実機の収録先は未確認 |

### REC-12 通話向け処理と入力指定を併用する

| 項目 | 内容 |
|---|---|
| **前提** | 内蔵・USB・Bluetooth のうち利用可能なマイクを指定して保存 |
| **手順** | 通話向け処理のオン・オフを切り替え、保存後に録音する。再生中と停止中を確認する |
| **期待結果** | 選択したマイクを使い、オフは `route=input_only`、オンは `route=voice_processing` で、`device_id=` が選んだ機器の ID と一致する。オンで既定以外の機器を選ぶと構成変更で止まる場合がある。構成できない組合せは開始エラーになり、次の録音を試せる。オンは音量低下が残る場合があるため、オフでの再生継続と区別して記録する |
| **検証状況** | 合成 Audio Unit の入力 element と EnableIO を書かないことは `InputConfigurationTests` で自動化済み。実機と AVAudioEngine の組合せは未確認 |

### PAL-08 ヘッダのクリックでフォルダ選択モードに入る

### PAL-12 対応していないアプリでは最近使ったフォルダに落ちる

|---|---|

### PAL-13 常駐索引が即座に出て、変更が自動で反映される

| 項目 | 内容 |
|---|---|
| **前提** | PAL-07 で Git リポジトリを最近使ったフォルダに記録してから Vox を再起動している |
| **手順** | そのフォルダを検索対象にしてパレットを開く。パレットを閉じて別アプリでファイルを1つ編集し、もう一度開く。続けてそのリポジトリでブランチを切り替えてから開く |
| **期待結果** | 1度目から候補が待たされずに出る。編集したファイルが `Changes` の先頭に出る（0.5 秒ほど遅れて届く）。ブランチを切り替えると追跡ファイルの一覧も入れ替わる。診断ログに `index_resident` と `index_rebuilt scope=changes` / `scope=tracked` が出て、パスは含まれない |
| **自動化済み** | `swift test --filter "ResidentIndexTests\|ResidentIndexStoreTests"`（読み直す範囲の判定、status だけの読み直しで追跡ファイルを保つこと、上限超過で捨てること、保持している索引を先に出すこと）。FSEvents の実監視だけが手動対象 |

### PAL-14 `⌘]` で検索対象の候補を巡る

| 項目 | 内容 |
|---|---|
| **前提** | 最近使ったフォルダが2件以上ある、または別 worktree の候補が出ている |
| **手順** | パレットを開き、`⌘]` を候補の数より1回多く押す。次に文字を打って絞り込んだ状態でもう一度押す |
| **期待結果** | 押すたびに別 worktree → 最近使ったフォルダの順で検索対象が切り替わり、一周すると押し始めたフォルダに戻る。パスは挿入されない。検索中でも同じ順で巡る。HUD のフォーカス移動（`Tab`）や `Enter` の挙動は変わらない |
| **自動化済み** | `swift test --filter "TargetCycleTests\|TargetCycleKeyTests"`（輪の順と一周、キーの見分け、選び直した後の写し直し）。`⌘]` が実際にパネルへ届くかだけが手動対象 |
