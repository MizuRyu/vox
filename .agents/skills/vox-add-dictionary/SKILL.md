# vox 辞書の候補出しと登録

辞書は `~/Library/Application Support/vox/dictionary.tsv`。1 行 = `認識される表記<TAB>入れたい表記`。
照合は表記の完全一致・最長一致で、読みの正規化はしない（ADR-019）。だから左辺は「認識結果に実際に出た文字列」を書く。

## 担当範囲

この skill が持つ: vox の履歴（`history.jsonl` の `raw_text`）からのカタカナ語の集計、
エージェントへの入力履歴からの誤変換の対の推定（`sessions`）、英字表記との対応づけ、選ばれた行の追記、登録済みの一覧。
渡す: 辞書が効かない・読み込めない切り分けは `vox-setup` の「よくあるトラブル」、
形式と照合の変更は ADR-019 / 021 と利用者。

## 事前条件

- 利用者が vox で何回か録音して確定している（履歴が無いと `suggest` は止まる）
- 履歴の本文を会話に出さない。スクリプトは語と件数だけを出す。`history.jsonl` を直接開かない

## 手順

スクリプトは `python3 .agents/skills/vox-add-dictionary/scripts/dictionary.py`（標準ライブラリだけ）。

1. 候補を数える。利用者が「普段キーボードで打つ文章」を持っていれば `--typed` に渡す
   （例: `git log --format=%s > /tmp/typed.txt` で自分の commit message、メモのファイル。複数可）

   ```sh
   python3 .agents/skills/vox-add-dictionary/scripts/dictionary.py suggest --typed /tmp/typed.txt
   ```

   表の列は 認識される表記 / 件数 / 英字の候補 / 打鍵回数 / 登録済み。件数 2 未満は出さない（`--min-count`）。
   英字の候補は素朴なローマ字と子音の並びで当てただけなので、外れも混ざる

2. 提案を 2 段で出す
   - **履歴に出た表記**（1 つ目の表）: 左辺としてそのまま登録できる。右辺は英字の候補か、利用者に聞く
   - **打鍵だけに出た英字の語**（2 つ目の表）: 履歴にまだ出ていない。カタカナ表記を推測して示し、
     利用者に一度話してもらってから `suggest --min-count 1` で実際の表記を確かめて登録する
3. 候補を絞る。優先は 固有名（製品名・サービス名・人名）> 略語 > 一般語。
   一般語（アプリ、ファイル、モデル）と、日本語の文でカタカナのまま書く語（コミット、プッシュ）は
   外すか「任意」と印を付ける。登録済み（「済」）は出さない。「一部」は残りの表記だけを提案する
4. 利用者が選んだ行を足す。1 引数 = 1 行で、タブは `$'\t'` で渡す

   ```sh
   python3 .agents/skills/vox-add-dictionary/scripts/dictionary.py add $'クロード\tclaude' $'ジェミニ\tgemini' $'ジェミニー\tgemini'
   ```

   - 長音の揺れ（表の「ジェミニ / ジェミニー」）は両方の左辺を登録する。片方だけだと「ジェミニー」が「geminiー」になる
   - 短い左辺は複合語の中でも置き換わる（「スキル → skill」は「スキルセット」を「skillセット」にする）。登録前に伝える
   - 1 つでも不正（タブが 1 つでない、改行を含む、左辺が空か `#` で始まる、既存と重複、64KiB 超）なら何も書かない。
     重複は本体と同じく正準等価で見て、既存の行番号を出す
5. 反映は次の録音から。設定画面の「辞書」→「更新」で件数と壊れた行を確かめてもらう

## エージェントへの入力履歴から誤変換を拾う（sessions）

Claude Code / Codex の入力履歴には、vox が認識した後の文が混ざる。そこにある誤変換（英語の名前が崩れた語。架空の例: ゾルテック → zoltech）は
1〜3 回しか出ないので、件数を数える `suggest` では見つからない。`sessions` は逆向きに探す。

1. 打鍵の発話（言いよどみの少ない発話。判定は vox-input-habits）から、3 回以上打った英字の語を「入れたい表記」の候補にする
2. 音声入力らしい発話を macOS の日本語の単語分割（`scripts/readings.swift`。Xcode の `swift` が要る）で読みに直し、
   連続する 1〜3 語の読みが候補の語と似ているものを「認識される表記」にする。似ている =
   子音の並び（`skeleton`）が同じか 1 音違いで、母音を残した音（`sounds`）も語の長さの半分以内で近い
3. 外すもの: 小文字の英単語を含む表記（英語で話した語）、記号を含む表記、正しい表記そのもの、
   正しい表記より打鍵の文でよく出る表記（普段の語）、漢字を含む表記で音が完全には同じでないもの

```sh
python3 .agents/skills/vox-add-dictionary/scripts/dictionary.py sessions            # 上位 300 行（1 分ほどかかる）
python3 .agents/skills/vox-add-dictionary/scripts/dictionary.py sessions --typed /tmp/typed.txt --limit 600
```

- 表の列は 認識される表記 / 入れたい表記の候補（ほか: 次点）/ 音声での件数 / 打鍵回数 / 近さ（一致・近い）/ 登録済み。
  並びは、音が同じ → 3 文字より長い語 → 普通の英単語でない語（固有名）→ 普段打たない表記ほど先
- 上位は「英語の名前をカタカナで話した形」（架空の例: ブロフィン → blorfin）が多い。どれも辞書の候補になる
- 誤変換は件数が少なく近さが「近い」のことが多いので、上位だけで切らず表の全部を読む。表は語と件数だけで、本文は出ない
- 出ないもの: 正しい表記が日本語の語、最初の音から違う語、正しい表記を 3 回未満しか打っていない語、
  単語分割が漢字の読みを取り違えた語。利用者が気づいた誤変換は、そのまま `add` で足す
- 提案は 2 の「候補を絞る」と同じ基準で絞り、登録は 4 の `add` で利用者が選んだ行だけ

### sessions を別の skill にしない理由

job は `suggest` と同じ（辞書に入れる行の候補を出し、利用者が選んだ行を `add` で足す）で、出力も登録の手順も同じ。
材料と推定の向きだけが違うので、同じ skill の subcommand にした。辞書の形式と照合（ADR-019 / 021）は変えない。
入力履歴の読み込みと「音声入力らしい」の判定は vox-input-habits の `habits.py` を import して使い、定義を 1 か所にする。

## 検証

- `dictionary.py list` で「左 → 右」と件数、読み込まれない行の番号を見る
- スクリプトの検査は `Tests/Tooling/dictionary-script-tests.sh`（`just tooling-test` に含まれる）。
  `sessions` の検査は合成した入力履歴で、漢字の誤変換・単語分割にまたがる語・1 音違い・英字と数字の語・外すものを確かめる

## 注意

- `add` はファイルが無ければ書き方のコメント付きで作る。この文面は `Sources/VoxApp/Settings/DictionaryStore.swift` の
  `template` と同じものを持っている。**変えるときは両方直す**（検査が一致を確かめる）
- 既存のファイルは末尾に足すだけで、他の行を書き換えない。権限は 0600 にそろえる

## やらないこと

- 履歴の本文・パス・他アプリの情報を会話や Issue に出さない。例は合成テキストで示す
- 行の削除・書き換えをスクリプトでしない。消す・直すときは設定画面の「辞書」の表（行を選んで「削除」）か、テキストエディタで行う
- 辞書の形式、照合規則、置換の位置を変えない（ADR-019 / 021）
- Vox 本体を起動しない（`AGENTS.md`）
