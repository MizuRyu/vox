# 入力の口癖とぼかし言葉の分析

材料は `~/.claude/history.jsonl`（`display`、`timestamp` ミリ秒）と `~/.codex/history.jsonl`（`text`、`ts` 秒）。
スラッシュコマンド、`!` コマンド、6 字未満、貼り付けの印を除いた日本語の発話を数える。

## 担当範囲

この skill が持つ: 音声入力らしい割合（月別）、語尾・ぼかし言葉の件数と文末の件数、1000 字あたりの密度（音声 / それ以外）、
依頼の形の件数、平均文字数、語ごとの当たり方の確認（抜粋）と使われ方の分類。
渡す: 誤変換の候補と辞書への登録は `vox-add-dictionary`（`sessions` がこの skill の読み込みと判定を使う）。

## 事前条件

- 履歴の本文を会話に出さない。スクリプトは語と件数だけを出す。`history.jsonl` を直接開かない
- 抜粋（`samples`）は秘密情報を伏せた短い窓（前 15 字・後 10 字）だけ。読むのはエージェントで、本人や Issue に貼らない

## 手順

スクリプトは `python3 .agents/skills/vox-input-habits/scripts/habits.py`（標準ライブラリだけ）。

1. 数える

   ```sh
   python3 .agents/skills/vox-input-habits/scripts/habits.py report          # 表
   python3 .agents/skills/vox-input-habits/scripts/habits.py report --json   # 同じ数字を JSON で
   ```

   - 音声入力らしい = 言いよどみ（えっと / えー / あの / なんか / まあ / うーん / うん / ちょっと / っていうか / なんだろう）が
     2 回以上、または 80 字を超えて 1 回以上。打鍵でも言いよどみは書くので推定値。言いよどみの一覧は `FILLERS` の 1 か所だけ
   - 「でしょうか」（丁寧な依頼・質問）は「でしょ」（確認）と別の行
2. 当たり方を確かめる。件数をそのまま信じず、変化を言う語ごとに抜粋を 10〜20 件読み、外れの割合を見る

   ```sh
   python3 .agents/skills/vox-input-habits/scripts/habits.py samples かな --n 20
   ```

   外れが多い語は、`ENDINGS` / `REQUESTS` の正規表現を直してから数え直す（直したら検査も足す）
3. 使われ方を分類する。抜粋を読んで、語ごとに次のどれに当たるかを書く（2026-10 の分析で見えた分け方）

   | 種類 | 語 | 読み方 |
   |---|---|---|
   | 柔らかい指示 | かも、〜したいかな、〜でいいかな | 決めたことを柔らかく言っている。実質は指示 |
   | 不確かな前提 | よね、っけ、でしょ？、気がする、多分 | 本人の記憶や観察からの仮説。当たっている保証はない。確かめてから進める |
   | 依頼の疑問形 | 〜できる？、できないかな、してもらっていいですか | ほぼ依頼。可否だけを聞いていることは少ない |
   | 評価を求める | どう思う？、いいんじゃね？、どうだろう | 賛否と理由を求めている |
   | 自己訂正 | いや、〜じゃなくて | 同じ発話の後の方が本意 |
   | 共感・前置き | じゃん | 確認を求めていない |

4. 結果を書く。数字は表で、使われ方は上の種類で。前回の結果があれば、月別の割合と密度の変化を並べる

## 検証

- 検査は `Tests/Tooling/habits-script-tests.sh`（`just tooling-test` に含まれる）。誤検出（なんかな、静かな、確かな、かなり、何もかも、でしょうか）と、
  平均文字数、秘密の伏せ方、本文を出さないことを合成データで確かめる

## やらないこと

- 発話の本文を会話・Issue・ファイルに写さない。数字と語、伏せた短い抜粋だけを扱う
- 本人の言い方を直すよう求めない。分析は読み方（どう受け取るか）のためのもの
- 結果から本人の性格や意図を断定しない。件数と抜粋で言えることだけを書く
