# prosody

vox の録音から、文末の声の高さなどの韻律で「？」を付けるか、「…」を付けたいかを判定する試作のツール一式。
本体（Swift）へ移す前に、本人の音声でどの程度当たるかを測る。判断の記録は [ADR-029](../../docs/adr/029-prosody-tuning-tool-outside-data.md)。

**このディレクトリにはコードと合成データの検査だけを置く。** 声・ラベル・学習した重み・評価の結果は
`~/Library/Application Support/vox/prosody/`（0700）に置き、リポジトリには入れない。置き場は `VOX_PROSODY_DATA` で替えられる。

## 使い方

```sh
cd benchmarks/prosody
uv run python tool/server.py          # http://127.0.0.1:8765 を開く（127.0.0.1 だけで待ち受ける）
uv run python -m prosody.train        # 集めたラベルで学習・評価。report.md と model.json をデータの置き場に書く
uv run python -m unittest discover -s tests -t .
```

vox 本体の設定「録音を保存する」（ADR-026）をオンにして話すと、`~/Library/Application Support/vox/recordings/` に録音がたまり、「自然な発話」の候補になる。

### 読み分け

同じ文を「↑ 語尾を上げる（問いかけ）」「↓ 下げる（独り言・言い切り）」「… ためらいながら」で読む。読み方ごとにまとめて進む。
Space で録音・停止、R で直前を聞く、⌫ で直前を取り消して同じ文に戻る、→ で飛ばす。一覧をクリックするとその文を録れる。

### 自然な発話

文の最後に付けたい記号を選ぶ。Space で文末 2.5 秒、Shift+Space で文全体を再生する（サーバーが区間だけを切り出して返す）。
1（？）／2（。）／3（判断できない）、E（…を付けたい）。「正しい文」の欄を書き換えると、誤字・読点・文末まで含めた正解の文として残る（⌘Enter）。
既定では「かな・の・か・ね・っけ」で終わる文だけを出す。

## 構成

| パス | 中身 |
|---|---|
| `tool/server.py` | 標準ライブラリだけの HTTP サーバー。録音の受け取りと取り消し、vox の録音の一覧と区間の切り出し、ラベルの保存 |
| `tool/index.html` | 録音とラベル付けの画面。ブラウザ内で 16kHz・モノラル・Int16 の wav にする |
| `prosody/yin.py` | YIN（numpy）。窓 1024・間隔 160・60〜600Hz・閾値 0.15（谷が無ければ 0.3 未満の最深の谷）。前後と比べて半分・倍に飛んだ値を戻す |
| `prosody/features.py` | 文末の特徴（上昇量、傾き、局所の高さ、ピーク位置、有声率、欠損、音量比、文末語の長さ、文字の語尾）。窓は最後に F0 が取れた位置に合わせる |
| `prosody/voxdata.py` | vox の録音（ADR-026 の wav と JSON）を文に分けて読む。データの置き場 |
| `prosody/dataset.py` | 読み分けとラベルから特徴表を作る。ためらいの読みは「？」の学習に使わない |
| `prosody/train.py` | 規則・L2 ロジスティック回帰・浅い勾配ブースティングを日付で分けた交差検証で比べ、ロジスティック回帰の重みを書き出す |
| `prosody/corrections.py` | vox の履歴と Claude Code・Codex のセッション記録を突き合わせ、貼った後に直した文を数える（結果はデータの置き場に書く） |
| `prosody/suggest.py` | ラベル付け画面の推奨（文字の規則、迷いやすい語尾か、ロジスティック回帰の確率） |
| `docs/` | 設計の元にした外部調査（ChatGPT、2026-10-18。出典は未確認）と、その問い |

## 現状

2026-10-18 時点。ラベル付きは読み分け 55 本（ためらいの 22 本は「？」の学習に使わない）と自然な発話 8 件。
評価は文ごとにまとめた交差検証（同じ文の上げ・下げを学習と評価に分けない）。

| モデル | 閾値 | 「？」の適合率 | 再現率 |
|---|---|---|---|
| 規則（末尾の上昇 2 半音） | — | 100%（10 件） | 38% |
| ロジスティック回帰（音声＋文字の語尾） | 0.5 | 91% | 77% |
| ロジスティック回帰（音声＋文字の語尾） | 0.909 | 100%（8 件） | 31% |

件数が少なく、1 件で 1.7% 動く。読み分けは大げさに読んだ音声なので、自然な発話では下がる見込み。

分かったこと:

- 上げ調子でも最後のモーラがかすれて F0 が取れないことが多い。末尾 0.4 秒の上位 10% の高さ（`peak_rise_st`）が最も効く
- Apple の語の区間末は、声の終わりより 0.1〜0.2 秒早いことがある。文末の声は次の文の頭までの 0.5 秒を探す
- 弱い語尾で 1 オクターブ外れた F0 を拾う。話者の中央値から 12 半音超と、ごく小さい音量のフレームは使わない
- Apple の語の区間は隙間なく続き、片は 1〜2 文字に割れる。沈黙から読点を置くと語の途中に入るので、読点の案は出さない
- vox の履歴 729 件をエージェントのセッション記録と突き合わせると、601 件中 585 件（97%）は直さずに送っていて、手で「？」を足した文は 0 件。正解の文はこのツールで集める

次は自然な発話のラベルを増やす（推奨を Enter で受けるだけで進む）。50 件を超えたら推奨の閾値（`suggest.MODEL_THRESHOLD`）を自然な発話の分布で決め直す。
