日本語の音声入力アプリで、韻律（プロソディ）とパラ言語情報を使って文末記号を決める機能を作りたい。「できるか」ではなく「具体的にどう作るか」を、専門家の立場で詳しく教えてほしい。最新の研究・ライブラリ状況はWeb検索で確認し、主張ごとに出典URLと公開年を付けること。確信度（高・中・低）も主張ごとに付けること。日本語で答えること。

## 前提（変えられない制約）

- macOS 26 / Apple Silicon、Swift 6 のネイティブアプリ。認識は Apple の SpeechTranscriber（ja-JP、端末内）。外部サーバーやクラウドAPIは使わない。Python の常駐プロセスは置けない（試作・オフライン分析は Python でよい）
- 認識結果には単語・区間ごとの音声時刻（audioTimeRange）を付けられる
- 認識に渡した音声を 16kHz・モノラル・Int16 の wav で保存できる（利用者は1人。数日で数百発話たまる）
- 確定後に挿入するまでの追加遅延は 50ms 程度に抑えたい
- 現状、Apple の出力は「〜ですか」「〜かな」で終わる文の多くに「？」ではなく「。」を付ける。語尾を上げるだけの疑問（「これでいい↑」）はテキストから判定できない
- 文字ベースの規則（「ですか」「っけ」→「？」）は別途入れる。知りたいのはその先

## やりたいこと（優先順）

1. 疑問の判定：文末の音声（声の高さの上昇など）から「？」を付けるか決める。特に「〜かな」が自問・独り言（下降）か問いかけ（上昇）かを区別したい
2. ためらい・自信のなさの検知：例「ちょっと自信ないんだよね。。。」のように、迷いがある発話の末尾に「…」や「。。。」を付ける、または画面上で示す
3. 1人の利用者の話し方の癖に合わせる（個人適応）

## 答えてほしいこと

A. 1 と 2 それぞれについて、使う特徴量（F0 の軌跡、文末何msを見るか、話者内正規化の方法、エネルギー、話速、ポーズ、母音の引き延ばし、声質など）と、日本語の文末イントネーション（X-JToBI の境界音調 L%H%・H% など）との対応

B. 手法の段階的な選択肢と推奨：(a) 規則・閾値、(b) 小さな分類器（ロジスティック回帰、勾配ブースティング）、(c) 事前学習済みの自己教師あり音声モデル（wav2vec 2.0 / HuBERT / WavLM など）の埋め込み＋軽い分類ヘッド、(d) 既存の感情・パラ言語モデルの流用。それぞれの精度の見込み、必要なデータ量、端末内での推論コスト

C. F0 抽出アルゴリズムの比較（YIN / pYIN / SWIPE / REAPER / CREPE / RMVPE など）。発話末のきしみ声（creaky voice）や息漏れで F0 が取れない問題への対処。Swift（Accelerate / vDSP）や Core ML で実装・変換する現実的な方法

D. 学習データとラベル：日本語で使える公開データセット（CSJ の X-JToBI ラベル、感情・パラ言語コーパスなど）の具体名と入手条件。利用者本人のデータに、手作業を最小にしてラベルを付ける方法（テキスト中の疑問形の文末を弱いラベルとして使う、利用者が後から手で「？」を足した履歴を使う、など）と、その偏りの問題

E. 評価の方法：何を指標にするか（疑問判定の適合率・再現率、誤って「？」や「…」を付けたときの害の扱い）、何件あれば判断できるか

F. 実装の落とし穴：疑問でも上がらない日本語の文（「〜の？」の平叙調、「ですか」の下降調など）、自然下降（declination）、背景雑音、短い発話、発話の区切り位置のずれ、個人差

G. 1週間で試作するならの具体的な手順（Python での試作 → 評価 → Swift 移植）

最後に、2（ためらいの検知）を製品に入れるべきか、あなたの立場と理由を明言すること。
